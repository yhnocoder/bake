bake 总览

bake 是一个面向技术博客的静态网站生成器，自带所见即所得的编辑器。它不仅支持 Markdown 基础语法与自定义扩展语法，还能在文章中嵌入交互组件，并在编辑器里直接调整组件的参数。bake build 生成静态网站，bake dev 在排好版的页面上编辑文章，修改保存回 Markdown 文件。本文档回答：bake 怎么用，一个博客仓库怎么组织，bake 由哪些模块组成，bake 和博客的边界在哪里。

bake 不包含任何文章、交互图或某个博客的首页。博客只通过配置文件和约定的目录把自己的内容交给 bake，bake 的代码不引用博客里的任何文件。

怎样使用

命令作用
bake new <path>在 content/ 下新建一篇只有 frontmatter 的文章，例如 bake new matrix-calculus/jacobian 生成 content/matrix-calculus/jacobian.md
bake dev启动开发服务器。页面右下角有「编辑」按钮，打开后在页面上直接编辑，见 编辑器
bake build生成静态网站到 dist/，见 构建与开发服务器
bake format把已有的 .md 文件统一成编辑器保存时的输出格式，见 内容格式

写一篇文章的过程：bake new 新建文件，bake dev 打开页面后点「编辑」，在页面上输入文字、公式，插入块和组件；停止输入后内容自动写回 .md 文件。在编辑器之外修改 .md 文件或组件代码时，页面就地更新，不刷新整页。推送到仓库后由 CI 运行 bake build 并发布。

编辑只在本机的开发服务器上进行，bake build 的输出不包含编辑器。

博客仓库怎么组织

my-blog/
├── package.json             依赖 bake；scripts 里只有 bake dev / bake build / test
├── bake.config.js           站点名、base path、默认主题、首页分类
├── components/              全局组件：所有文章都能用，文件名就是组件名
│   ├── topic-grid.js            首页的分类卡片网格
│   └── lib/                     组件共用的脚本，本身不是组件
├── content/                 文章，按主题分目录
│   ├── index.md                 首页，slug 为 /
│   ├── matrix-calculus/
│   │   ├── index.md             slug 为 matrix-calculus
│   │   ├── deep-learning.md     slug 为 matrix-calculus/deep-learning
│   │   ├── assets/neuron.png    文章里写 ![…](./assets/neuron.png)
│   │   ├── components/          只在这个主题的文章里能用的组件
│   │   │   └── gradient-figure.js
│   │   └── notes/               写作笔记和资料，不生成页面
│   └── word2vec/index.md
├── blocks/                  只有这个博客使用的块类型
├── layouts/                 这个博客新增或覆盖的版式，可以没有
├── themes/                  主题 CSS
└── tests/                   这个博客自己的页面测试
  • content/ 下每个 .md 文件生成一个页面。页面地址由 frontmatter 的 slug 决定，与文件在 content/ 中的位置无关，规则见 构建与开发服务器。notes/、components/、assets/ 目录里的文件不生成页面。
  • 组件名在全站唯一。主题目录下的组件和全局组件重名时，构建报错。理由：浏览器里一个 custom element 名字只能对应一个定义。
  • 首页是 content/index.md，首页的卡片网格是一个组件，数据来自 bake 提供的全部文章 frontmatter，见 扩展接口。

bake 由哪些模块组成

核心是内容格式模块：它定义哪些 Markdown 写法合法、每种块类型有哪些属性。渲染模块和编辑器都从这里取定义，所以编辑器里看到的就是发布后的页面。

模块做什么
formatremark 插件组合、块类型登记表、frontmatter 校验。不认识的指令报错
render把一篇 .md 渲染成 HTML 片段和目录：标题 id、章节、公式 SVG、图片、表格、旁注、站内链接
layouts把渲染结果套进整页 HTML。内置 essay、paper、bento
site读取配置，按 slug 发现页面，发现组件和主题，把一篇文章经过渲染和版式生成整页 HTML。构建和开发服务器都通过它渲染整页，两者生成的页面相同
editor浏览器里的编辑器。节点定义、属性面板、插入菜单由块类型登记表和组件登记表生成
devVite 插件：请求页面时通过 site 即时渲染，提供读写 .md 的接口，监视文件变化并通知页面
build通过 site 生成每页 HTML，打包每页用到的组件，处理图片，检查站内链接

bake 仓库怎么组织

bake/
├── src/
│   ├── format/      remark 插件组合、块类型登记表、frontmatter 校验
│   ├── blocks/      内置块类型，每种一个文件，渲染规则和编辑器节点放在一起
│   ├── render/
│   ├── layouts/     essay.js、paper.js、bento.js、head.js
│   ├── styles/      版式和内置块的 CSS，只使用主题变量；variables.js 列出主题变量名
│   ├── client/      浏览器脚本：page.js 是页面入口，sidenotes.js 导出旁注对齐与悬停高亮
│   ├── site/        读取配置、页面、组件和主题，渲染整页；pages.js 计算页面地址
│   ├── editor/
│   ├── dev/
│   ├── build/
│   └── cli.js       bake new | dev | build | format
├── examples/
│   ├── minimal/                  覆盖全部功能的最小博客
│   │   ├── bake.config.js
│   │   ├── content/features.md   一页展示全部功能
│   │   ├── content/paper.md      paper 版式
│   │   ├── content/bento.md      bento 版式
│   │   ├── components/demo-plot.js
│   │   └── themes/default.css
│   └── learn-by-visualization/   真实博客，验证 bake 能承载已有内容
└── test/

bake 的测试只针对 examples/。examples/minimal/content/features.md 在一页里使用每一种块、公式、旁注、站内引用、组件、图片和表格；新增一种内置功能时，同时在这一页加上它的用法。

测试检查什么
渲染features.md、paper.md、bento.md 生成的 HTML 与保存的结果一致
往返每个 .md 文件载入编辑器后不做修改直接导出，结果与原文件逐字节相同
编辑器在浏览器里打字、改公式、插入每种块、改组件属性后，文件里只有对应的几行变化
监视在编辑器之外修改 .md 后页面不刷新就更新；编辑器里有未保存的修改时提示冲突
复制从生成的页面复制一段再粘贴进编辑器，得到的 Markdown 与原文件里的那一段相同
边界src/ 里没有文件引用 src/ 以外的路径

技术选型

用途选择理由
编辑器Milkdown（ProseMirror 加 remark）。只使用 @milkdown/core、ctx、transformer、utils、prose、preset-commonmark、preset-gfm、plugin-history，以及后续功能需要的 plugin-block、plugin-slash；不使用 Crepe 和界面组件，版本写精确值与渲染共用 remark 解析，编辑器和页面对同一份 Markdown 的理解一致
开发服务器和打包Vite按模块热更新，保存时不刷新整页
公式MathJax，构建时输出 SVG页面不需要加载 MathJax，打开时不跳动
组件custom element；可以用 SolidJS（solid-element）编写不强制框架，简单的图用纯 JS 更短
动画Motion（不依赖 React 的版本）折叠、旁注、预览卡片和编辑器面板的动画；颜色变化用 CSS；遵守系统的减少动态效果设置
文字测量Pretext，只提供给组件SVG 和 canvas 里的文字不会自动换行，组件用它按宽度断行。正文由浏览器排版，不使用它

不使用 Eleventy、Hugo 这类自带 Markdown 解析器的生成器。理由：它们的解析器与编辑器使用的 remark 不同，同一份 Markdown 在编辑器和页面上可能显示不一样。

Bake v0.1 不包含的功能

dark mode、手机适配、AI、导出成 HTML / PDF / Typst / Markdown、设置界面。这些在 Bake v0.1 完成后另行设计。
