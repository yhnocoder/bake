编辑器

编辑器运行在 bake dev 打开的页面上：点「编辑」后，排好版的页面本身变成可编辑的，修改自动写回 .md 文件。本文档写编辑器的界面、每种内容的编辑方式、保存与冲突、复制与粘贴，以及公式的渲染策略。

编辑器是什么样子

A. 页面顶部版式原有的标题区，标题直接输入。
B. 目录版式原有的目录，随标题实时更新。
C. 正文Milkdown 编辑区，样式与发布的页面相同。空行输入 / 打开插入菜单。
D. 状态栏右下角：「编辑」开关、保存状态（已保存、保存中、冲突）。

右侧栏在编辑时显示旁注，旁注可以直接输入。选中组件或带属性的块时，属性面板出现在右侧栏顶部；关闭面板后旁注恢复显示。

编辑器只存在于 bake dev。bake build 的输出不包含编辑器代码，也不包含「编辑」按钮。

打开和关闭编辑器时发生什么

开发服务器在页面中加入编辑器入口模块 src/editor/index.js，它只负责「编辑」开关和状态栏。编辑器本身的代码在第一次点击「编辑」时才加载。点击「编辑」后：

  1. 请求 /__bake/source，取得文件原文和哈希值。
  2. 记下页面上已经渲染好的公式：<article> 中每个带 data-tex 的元素，按行内或独立加 TeX 源码记入一个表，见 公式在编辑器里怎么渲染。
  3. 解析原文。frontmatter 原文存为文档根节点的属性，修改 frontmatter 是一个普通的编辑步骤，可以撤销，与正文一起自动保存。
  4. 在 <article> 里创建编辑器，替换原有内容。<article> 的 class 和版式结构不变，所以编辑器的样式与页面相同。

文章违反内置块的结构规则，或者有编辑器无法原样保存的写法（例如行内 HTML、组件指令带方括号文字）时，编辑器不打开，<article> 保持阅读视图，状态栏显示「文章有结构错误，修正后才能编辑」。具体错误由开发服务器的错误列表给出。

再次点击「编辑」关闭编辑器：等待未完成的保存，再请求页面最新的渲染结果替换 <article> 的内容，然后在 window 上发出 bake:page-updated 事件，旁注位置等页面脚本据此重新计算。

块怎样变成编辑器节点

开发服务器提供虚拟模块 virtual:bake/registry，导出块类型登记表和组件的属性表（每个组件的 static properties）。编辑器按块的 form 生成节点：

块的 form编辑器节点
container块节点，内容是一个或多个块。指令方括号里的文字（例如 :::fold[推导细节] 的标题、:::callout[向量说明] 的名称）是第一个子节点，可以直接输入；折叠块必须有这个子节点，其他块的这个子节点删空后保存时不写方括号
leaf块节点，内容是方括号里的行内文字
text行内格式（mark），方括号里的文字可以直接编辑

内置块的结构规则（见 内容格式）写进编辑器的 schema：导语只能是第一个块，卡片网格只含卡片，参考文献只含一个列表，出处只能在引用块末尾。插入、拖动和粘贴共用这一份约束，产生不符合规则的文档的操作不会执行。导语和出处只由用户主动插入，在引用块最后一段或文章开头按 Enter 新建的是普通段落。副标题必须紧跟标题，这条规则无法写进 schema，由一个检查函数判断。

节点的 DOM 由块定义的 render 生成，与页面上的 HTML 相同；render 输出中不属于内容的部分只显示，不能编辑。块和组件的属性存在节点上，原样写回。组件（指令名含 -）在编辑器里创建同名的 custom element，组件照常运行，<figcaption> 是可以输入的图题。

每种内容怎么编辑

Mod 在 macOS 上是 Command，其他系统上是 Ctrl。

文章的最后一个块是只含图片的段落或其他不能放光标的块时，编辑器在末尾保留一个空段落，用来继续输入；保存时末尾的空段落不写入文件。理由：图片显示为块级的 <figure>，浏览器无法把光标放在它后面。

段落的 ^id 和标题的 {#id} 属于块的内容：剪切或删除使段落或标题变空时，它的 id 一起删除，撤销时恢复。理由：留下的空块会保存成只有 id 的一行，并占用这个 id，把剪切的内容粘贴到别处时 id 会因为重复而被删除。

插入菜单

在空行输入 / 打开插入菜单，继续输入文字筛选，Enter 插入。菜单列出全部内置块类型、博客 blocks/ 里的块类型，以及当前文章能使用的组件（全局组件和本主题的组件）。菜单项由块类型登记表和组件登记表生成，新增块类型或组件后不需要修改编辑器。

属性面板

属性面板的控件由定义生成：

type控件写回的属性值
number滑块加数字输入框，使用 min、max、step数字
string单行输入框字符串
boolean开关为 true 时写属性名，为 false 时不写
enum下拉框，选项来自 options选中的字符串

没有选中任何块时，属性面板显示页面属性：通用 frontmatter 字段和当前版式声明的字段，见 内容格式 的 frontmatter 一节。修改后写回文件开头的 frontmatter。

拖动滑块时组件实时重画，文件在停止拖动后写回。属性值等于 default 时不写进 Markdown。理由：文件里只保留与默认值不同的属性，默认值修改后所有没有显式设置的地方一起生效。

怎样移动块

鼠标移到一个块上时，块的左侧显示拖动手柄 ⋮⋮。按住手柄拖动，目标位置显示一条放置线，松开后块移到放置线处。点击手柄打开块菜单，菜单里有「删除」「复制一份」「上移」「下移」，结果不符合结构规则的项置灰。

  • 手柄指向指针所在的最内层可以拖动的块，同时显示它外层每一个可以拖动的容器块的手柄。理由：加宽、边注这类容器块的面积完全被子块覆盖，只显示最内层的手柄时拖不动它们。外层手柄与内层手柄纵向重叠时，外层手柄向左让开一个手柄的宽度。卡片网格中指针在哪张卡片上，手柄就指向哪张卡片。
  • 手柄与块的第一行文字垂直居中；组件、表格、公式块、HTML 块、分隔线和图片所在的段落，手柄与块的顶部对齐。指针从块向左移向手柄的途中，手柄不重新定位。
  • 可以拖动的块：段落（图片所在的段落）、标题、列表项、整个列表、引用、代码块、公式块、组件、表格、独立的 HTML 块、分隔线和所有容器块。容器块连同里面的内容一起移动。
  • 没有手柄的块：指令方括号里的文字、副标题、出处、导语、注释和注释里的内容、表格的行和单元格，以及取出后父节点不再符合结构规则的块，例如列表项的第一个段落、只有一个段落的提示框里的这个段落、只有一张卡片的卡片网格里的这张卡片。指针在这样的块上时，手柄指向外层第一个可以拖动的块。
  • 标题后面紧跟副标题时，两者作为一个整体拖动、删除、复制和移动。
  • 放置线按指针所在的块判断位置：指针在块的前半部分时放在块之前，否则放在块之后。这个位置不符合结构规则时，放置线显示在外层块之前或之后的合法位置；都不合法时不显示放置线，松开后文档不变。例如段落拖到两张卡片之间时，放置线在卡片网格之外；卡片只能放进卡片网格。
  • 放置线在一般的块之间是一条横线，位于前后两个块之间空白的中间，宽度等于所在容器的内容宽度；在卡片网格里是一条竖线，位于两张卡片之间，高度等于卡片的高度。理由：卡片左右相邻，横线表示不了插在两张卡片之间。
  • 「复制一份」把副本放在原块之后。副本去掉标题的 {#id}、段落的 ^block-id 和独立公式的 \label，理由：页面内 id 和公式标签重复时渲染报错。副本中的旁注编号改用新名字，注释内容与原注释相同，见 旁注怎么编辑。
  • 移动或删除带旁注编号的段落时，注释名不变，注释跟着段落移动或一起删除，编号按新的顺序重新计算。
  • 键盘操作：Mod-Shift-↑ 和 Mod-Shift-↓ 把光标所在的最内层可以拖动的块上移或下移一个位置，光标留在块内原来的字符处，连续按键继续移动同一个块。块已经是容器里的第一个或最后一个块时，移到容器块之前或之后；移出后不符合结构规则时不移动。
  • 拖动、块菜单和键盘的每次操作对应一步撤销，Mod-Z 一次恢复原样。
  • 块移动时使用 Motion 动画，其他块让出位置的过程也有过渡；系统开启减少动态效果时直接移动。

尺寸：手柄 18px × 24px，右边缘距块左边缘 6px；放置线粗 2px；块菜单宽 8em。颜色只使用主题变量。

手柄由 bake 按指针位置定位，拖动使用浏览器原生的拖放事件，放下时生成一个 ProseMirror 事务。不使用 Milkdown 的 block 插件，理由：它在编辑区的水平中线上取点、把容器的第一个子块改指向父节点，这两条规则不能配置，卡片网格只能拖中间一列。

旁注怎么编辑

注释是编辑器文档中的一个块，位于引用它的顶层块之后，与保存的文件中的位置相同。右侧栏是这个块的显示位置：注释块输出与页面相同的 <aside class="sidenote">，由页面的 CSS 和对齐代码放进右侧栏。输入、撤销和保存都只处理这一个文档，没有另一份注释状态。

  • 在正文中按 Mod-Alt-F 或输入 [^，在光标处插入一个新编号，右侧栏出现一条空注释，光标移到注释里。光标在注释里时插入命令不可用，因为注释里不能有脚注引用。
  • 注释里可以输入段落、公式、链接和列表。
  • 删除正文里的编号时，对应注释一起删除；撤销时一起恢复。删除或剪切带编号的块时同样处理。
  • 编号随增删实时更新。
  • 编辑器和发布的页面使用同一份对齐代码，见 内容格式中旁注的排版。文档变化后编辑器重新对齐一次，因为在注释里输入时注释变高，正文容器的尺寸可能不变。
  • 已有的脚注名保持不变；新插入的注释命名为 [^n1]、[^n2]，跳过文件中已经使用的名字。还没有输入内容的空注释保存为 [^n1]:，页面上显示一条只有编号的空注释。
  • 复制或剪切带编号的内容时，对应的注释一起放进剪贴板，粘贴后注释放在引用所在的顶层块之后。粘贴后同一个名字被引用多次时，原有的引用保留名字，新粘贴的引用和它的注释改用新名字，注释内容不变。
  • 文件中没有被引用的注释（构建时报错）在编辑器里保留在文末，不显示编号，保存时原样写回。理由：不丢失已经写下的内容。
  • 窗口宽度小于 1100px 时没有右侧栏，注释显示在它在文档中的位置，即引用所在的顶层块之后。页面上注释显示在引用所在的段落之后，两者在引用位于列表、引用块或容器块里时不同。理由：注释在文档中的位置只有一份。

注释在文档中位于两个正文块之间，ProseMirror 默认的合并操作会把正文接进注释，或者把注释的内容拉进正文。编辑器对下面四种按键另行处理，方向键、Enter 和其他按键使用默认行为：

按键光标位置行为
Backspace注释第一个文本块的开头注释为空时删除这条注释和它的编号，光标回到编号原来的位置；注释不为空时不做任何事
Delete注释最后一个文本块的末尾不做任何事
Backspace顶层文本块的开头，前面紧挨着注释越过这些注释，把这个文本块的内容接到注释前面最后一个文本块的末尾；那里没有文本块时（例如以图片或公式块结尾）不做任何事
Delete顶层块最后一个文本块的末尾，后面紧挨着注释越过这些注释，把后面第一个文本块的内容接到当前文本块的末尾；后面不以文本块开始时不做任何事

站内链接怎么插入

按 Mod-K 或在插入菜单选择「链接」，打开链接选择器。输入文章标题、标题文字或段落 id，候选列表显示全站的文章、标题和带 ^block-id 的段落，按匹配程度排序。选中后填入路径和 #id，链接文字默认是目标的标题文字。输入以 http 开头的地址时作为外部链接插入。

编辑器里鼠标停留在站内链接上同样显示预览，内容由开发服务器即时渲染。候选列表的数据来自开发服务器的 /__bake/sections 接口，见 构建与开发服务器。

修改怎么保存

  1. 每次修改后等待 800ms，期间没有新的修改时保存。
  2. 编辑器用 Markdown 输出器把整篇文档转成文本，连同载入时文件内容的哈希值发给 POST /__bake/save。
  3. 开发服务器比较磁盘上文件的哈希值。相同时写入文件，返回新的哈希值；不同时不写入，返回冲突。
  4. 保存成功后状态栏显示「已保存」。开发服务器识别出这次文件变化来自编辑器，不重新渲染页面，也不通知页面更新。
  5. 修改 slug 后页面地址改变，开发服务器返回新地址，编辑器改变浏览器地址，之后的请求使用新地址。
  6. 编辑器在 window 上发出 bake:editor-saved 事件，detail 为 { url, hash, frontmatter }，页面外框据此更新。

状态栏显示「已保存」「保存中」「保存失败」或「冲突」。保存失败或冲突时，状态栏显示原因，编辑器保留当前内容，不丢弃修改。冲突时状态栏提供两个按钮：「使用磁盘上的版本」用磁盘上的内容重新载入编辑器；「保留我的修改并覆盖」用磁盘内容的哈希值重新保存编辑器的内容。

在编辑器之外修改文件时会怎样

情况结果
编辑器未打开，.md 被修改页面就地替换正文、目录和旁注，滚动位置保持不变，不刷新整页
编辑器已打开，没有未保存的修改，.md 被修改编辑器重新载入文件内容，光标放回序号相同的块的开头

复制与粘贴怎么处理

粘贴进编辑器的内容自动转换成对应的格式。从编辑器或发布的页面复制出去时，剪贴板的纯文本是 Markdown，同时附带 HTML，粘贴到支持格式的应用时保留格式。

粘贴进编辑器

来源剪贴板内容转换结果
bake 生成的页面HTML，元素上带 data-tex 和 data-md与原文相同的公式、组件、旁注和块
其他网页HTML标题、列表、链接、表格、代码块、加粗、斜体对应到编辑器格式；不认识的标签只保留文字
网页里的公式MathJax 或 KaTeX 输出中的 TeX 源码，或 MathML公式
VS Code 等代码编辑器纯文本和 vscode-editor-data 中的语言名带语言名的代码块
Markdown 文本纯文本按 Markdown 解析后插入，公式和表格保留
Excel、Numbers、Google SheetsHTML 表格GFM 表格
截图、图片文件、SVG 文件图片数据文件存进文章所在目录的 assets/，插入图片
SVG 源码以 <svg 开头的文本存成 assets/ 里的 .svg 文件，插入图片

纯文本按 Markdown 解析的条件：文本中出现 Markdown 的块级写法（标题、列表、表格、代码块、公式块）。不满足时按普通文本插入。按 Mod-Shift-V 始终按普通文本插入。

粘贴的图片文件名是内容哈希的前 8 位加原扩展名，例如 assets/3f9a1c2e.png。理由：同一张图片粘贴两次只保存一个文件。图片通过 POST /__bake/asset 写入。

复制出去

  • 编辑器里：选区用保存时使用的同一个 Markdown 输出器转成文本，复制出去的内容和 .md 文件里的写法相同。
  • 发布的页面：页面空闲时加载复制脚本，拦截 copy 事件，把选区的 HTML 转回 Markdown。构建时给公式加 data-tex，给组件、旁注和指令块加 data-md（该元素对应的 Markdown 源码），转换时直接使用这些属性。选区只包含公式或组件的一部分时，按整个元素处理。

公式在编辑器里怎么渲染

打开编辑器时，编辑器直接使用页面上已经渲染好的公式 SVG，不在浏览器里重新渲染。只有被修改的公式才在浏览器里用 MathJax 渲染，结果按 TeX 源码缓存，同一个公式只渲染一次。MathJax 只在第一次修改公式时加载。

编辑器和构建读取同一份 MathJax 配置（宏和字体），两边输出的 SVG 相同。保存写回文件时开发服务器不重新渲染页面，所以修改一个公式只引起这一个公式的渲染。新公式用到的字形加入页面上的 mathDefs。

带 \label 的编号公式和 \eqref 显示打开编辑器时的编号。新增或删除编号公式后，编号在关闭编辑器重新渲染页面时更新；编辑器之外修改文件导致重新载入时，编号按新内容重新计算。理由：编辑时重新编号会让后面所有编号公式重新渲染。
