编辑器

编辑器运行在 bake dev 打开的页面上：点「编辑」后，排好版的页面本身变成可编辑的，修改自动写回 .md 文件。本文档写编辑器的界面、每种内容的编辑方式、保存与冲突、复制与粘贴，以及公式的渲染策略。

编辑器是什么样子

A. 页面顶部版式原有的标题区，标题直接输入。
B. 目录版式原有的目录，随标题实时更新。
C. 正文Milkdown 编辑区，样式与发布的页面相同。空行输入 / 打开插入菜单。
D. 状态栏右下角：「编辑」开关、保存状态（已保存、保存中、冲突）。

右侧栏在编辑时显示旁注，旁注可以直接输入。选中组件或带属性的块时，属性面板出现在右侧栏顶部；关闭面板后旁注恢复显示。

编辑器只存在于 bake dev。bake build 的输出不包含编辑器代码，也不包含「编辑」按钮。

打开和关闭编辑器时发生什么

开发服务器在页面中加入编辑器入口模块 src/editor/index.js，它只负责「编辑」开关和状态栏。编辑器本身的代码在第一次点击「编辑」时才加载。点击「编辑」后：

  1. 请求 /__bake/source，取得文件原文和哈希值。
  2. 记下页面上已经渲染好的公式：<article> 中每个带 data-tex 的元素，按行内或独立加 TeX 源码记入一个表，见 公式在编辑器里怎么渲染。
  3. 解析原文。frontmatter 原文存为文档根节点的属性，修改 frontmatter 是一个普通的编辑步骤，可以撤销，与正文一起自动保存。
  4. 在 <article> 里创建编辑器，替换原有内容。<article> 的 class 和版式结构不变，所以编辑器的样式与页面相同。

文章违反内置块的结构规则，或者有编辑器无法原样保存的写法（例如行内 HTML、组件指令带方括号文字）时，编辑器不打开，<article> 保持阅读视图，状态栏显示「文章有结构错误，修正后才能编辑」。具体错误由开发服务器的错误列表给出。

再次点击「编辑」关闭编辑器：等待未完成的保存，再请求页面最新的渲染结果替换 <article> 的内容，然后在 window 上发出 bake:page-updated 事件，旁注位置等页面脚本据此重新计算。

块怎样变成编辑器节点

开发服务器提供虚拟模块 virtual:bake/registry，导出块类型登记表和组件的属性表（每个组件的 static properties）。编辑器按块的 form 生成节点：

块的 form编辑器节点
container块节点，内容是一个或多个块。指令方括号里的文字（例如 :::fold[推导细节] 的标题、:::callout[向量说明] 的名称）是第一个子节点，可以直接输入；折叠块必须有这个子节点，其他块的这个子节点删空后保存时不写方括号
leaf块节点，内容是方括号里的行内文字
text行内格式（mark），方括号里的文字可以直接编辑

内置块的结构规则（见 内容格式）写进编辑器的 schema：导语只能是第一个块，卡片网格只含卡片，参考文献只含一个列表，出处只能在引用块末尾。插入、拖动和粘贴共用这一份约束，产生不符合规则的文档的操作不会执行。副标题必须紧跟标题，这条规则无法写进 schema，由一个检查函数判断。

节点的 DOM 由块定义的 render 生成，与页面上的 HTML 相同；render 输出中不属于内容的部分只显示，不能编辑。块和组件的属性存在节点上，原样写回。组件（指令名含 -）在编辑器里创建同名的 custom element，组件照常运行，<figcaption> 是可以输入的图题。

插入菜单

在空行输入 / 打开插入菜单，继续输入文字筛选，Enter 插入。菜单列出全部内置块类型、博客 blocks/ 里的块类型，以及当前文章能使用的组件（全局组件和本主题的组件）。菜单项由块类型登记表和组件登记表生成，新增块类型或组件后不需要修改编辑器。

属性面板

属性面板的控件由定义生成：

type控件写回的属性值
number滑块加数字输入框，使用 min、max、step数字
string单行输入框字符串
boolean开关为 true 时写属性名，为 false 时不写
enum下拉框，选项来自 options选中的字符串

没有选中任何块时，属性面板显示页面属性：通用 frontmatter 字段和当前版式声明的字段，见 内容格式 的 frontmatter 一节。修改后写回文件开头的 frontmatter。

拖动滑块时组件实时重画，文件在停止拖动后写回。属性值等于 default 时不写进 Markdown。理由：文件里只保留与默认值不同的属性，默认值修改后所有没有显式设置的地方一起生效。

怎样移动块

鼠标移到一个块上时，块的左侧显示拖动手柄 ⋮⋮。按住手柄拖动，目标位置显示一条横线，松开后块移到横线处。点击手柄打开块菜单，菜单里有「删除」「复制一份」「上移」「下移」。

  • 可以拖动的块：段落、标题、列表项、引用、代码块、公式块、图片、组件、表格、独立的 HTML 块和所有容器块。容器块连同里面的内容一起移动。
  • 块可以拖进或拖出容器块，例如把一个段落拖进提示框，或者把卡片网格里的一张卡片拖到另一个位置。拖进容器后不符合容器结构的位置不显示横线，例如卡片网格里只能放卡片。
  • 移动带旁注编号的段落时，旁注跟着段落移动，编号按新的顺序重新计算。
  • 键盘操作：Mod-Shift-↑ 和 Mod-Shift-↓ 把光标所在的块上移或下移一个位置。
  • 移动可以用 Mod-Z 撤销，一次移动对应一步撤销。
  • 块移动时使用 Motion 动画，其他块让出位置的过程也有过渡；系统开启减少动态效果时直接移动。

拖动使用 Milkdown 的 block 插件（@milkdown/kit/plugin/block）提供的手柄定位和 ProseMirror 原生的节点拖放。

旁注怎么编辑

注释是编辑器文档中的一个块，位于引用它的顶层块之后，与保存的文件中的位置相同。右侧栏是这个块的显示位置：注释块输出与页面相同的 <aside class="sidenote">，由页面的 CSS 和对齐代码放进右侧栏。输入、撤销和保存都只处理这一个文档，没有另一份注释状态。

  • 在正文中按 Mod-Alt-F 或输入 [^，在光标处插入一个新编号，右侧栏出现一条空注释，光标移到注释里。光标在注释里时插入命令不可用，因为注释里不能有脚注引用。
  • 注释里可以输入段落、公式、链接和列表。
  • 删除正文里的编号时，对应注释一起删除；撤销时一起恢复。删除或剪切带编号的块时同样处理。
  • 编号随增删实时更新。
  • 编辑器和发布的页面使用同一份对齐代码，见 内容格式中旁注的排版。文档变化后编辑器重新对齐一次，因为在注释里输入时注释变高，正文容器的尺寸可能不变。
  • 已有的脚注名保持不变；新插入的注释命名为 [^n1]、[^n2]，跳过文件中已经使用的名字。还没有输入内容的空注释保存为 [^n1]:，页面上显示一条只有编号的空注释。
  • 复制或剪切带编号的内容时，对应的注释一起放进剪贴板，粘贴后注释放在引用所在的顶层块之后。粘贴后同一个名字被引用多次时，原有的引用保留名字，新粘贴的引用和它的注释改用新名字，注释内容不变。
  • 文件中没有被引用的注释（构建时报错）在编辑器里保留在文末，不显示编号，保存时原样写回。理由：不丢失已经写下的内容。
  • 窗口宽度小于 1100px 时没有右侧栏，注释显示在它在文档中的位置，即引用所在的顶层块之后。页面上注释显示在引用所在的段落之后，两者在引用位于列表、引用块或容器块里时不同。理由：注释在文档中的位置只有一份。

注释在文档中位于两个正文块之间，ProseMirror 默认的合并操作会把正文接进注释，或者把注释的内容拉进正文。编辑器对下面四种按键另行处理，方向键、Enter 和其他按键使用默认行为：

按键光标位置行为
Backspace注释第一个文本块的开头注释为空时删除这条注释和它的编号，光标回到编号原来的位置；注释不为空时不做任何事
Delete注释最后一个文本块的末尾不做任何事
Backspace顶层文本块的开头，前面紧挨着注释越过这些注释，把这个文本块的内容接到注释前面最后一个文本块的末尾；那里没有文本块时（例如以图片或公式块结尾）不做任何事
Delete顶层块最后一个文本块的末尾，后面紧挨着注释越过这些注释，把后面第一个文本块的内容接到当前文本块的末尾；后面不以文本块开始时不做任何事

站内链接怎么插入

按 Mod-K 或在插入菜单选择「链接」，打开链接选择器。输入文章标题、标题文字或段落 id，候选列表显示全站的文章、标题和带 ^block-id 的段落，按匹配程度排序。选中后填入路径和 #id，链接文字默认是目标的标题文字。输入以 http 开头的地址时作为外部链接插入。

编辑器里鼠标停留在站内链接上同样显示预览，内容由开发服务器即时渲染。候选列表的数据来自开发服务器的 /__bake/sections 接口，见 构建与开发服务器。

修改怎么保存

  1. 每次修改后等待 800ms，期间没有新的修改时保存。
  2. 编辑器用 Markdown 输出器把整篇文档转成文本，连同载入时文件内容的哈希值发给 POST /__bake/save。
  3. 开发服务器比较磁盘上文件的哈希值。相同时写入文件，返回新的哈希值；不同时不写入，返回冲突。
  4. 保存成功后状态栏显示「已保存」。开发服务器识别出这次文件变化来自编辑器，不重新渲染页面，也不通知页面更新。
  5. 修改 slug 后页面地址改变，开发服务器返回新地址，编辑器改变浏览器地址，之后的请求使用新地址。
  6. 编辑器在 window 上发出 bake:editor-saved 事件，detail 为 { url, hash, frontmatter }，页面外框据此更新。

状态栏显示「已保存」「保存中」「保存失败」或「冲突」。保存失败或冲突时，状态栏显示原因，编辑器保留当前内容，不丢弃修改。冲突时状态栏提供两个按钮：「使用磁盘上的版本」用磁盘上的内容重新载入编辑器；「保留我的修改并覆盖」用磁盘内容的哈希值重新保存编辑器的内容。

在编辑器之外修改文件时会怎样

情况结果
编辑器未打开，.md 被修改页面就地替换正文、目录和旁注，滚动位置保持不变，不刷新整页
编辑器已打开，没有未保存的修改，.md 被修改编辑器重新载入文件内容，光标放回序号相同的块的开头
编辑器已打开，有未保存的修改，.md 被修改状态栏显示冲突，提供「使用磁盘上的版本」和「保留我的修改并覆盖」两个按钮
组件的 .js 被修改Vite 热更新这个组件，页面上该组件的实例重新创建，属性保持不变
主题或版式被修改主题 CSS 热更新；版式修改后就地替换整个 <body> 内容，不刷新整页

复制与粘贴怎么处理

粘贴进编辑器的内容自动转换成对应的格式，保存后的写法与 bake format 相同。从编辑器或发布的页面复制出去时，剪贴板的纯文本是 bake 格式的 Markdown，同时附带 HTML，粘贴到支持格式的应用时保留格式。

剪贴板标记

bake 写剪贴板时，HTML 的最外层是 <div data-bake-markdown>，表示同时写入的纯文本就是 bake 格式的 Markdown。编辑器粘贴时看到这个标记就直接使用纯文本。理由：bake 页面和编辑器之间复制粘贴的结果与原文逐字相同，不经过 HTML 转换。

粘贴进编辑器

粘贴时按下表从上到下检查剪贴板，第一个符合的规则决定结果。

顺序条件结果
1光标在代码块里按纯文本插入
2这次粘贴由 Mod-Shift-V 触发按纯文本插入
3有图片文件，并且没有 HTML 或 HTML 中除 img 元素以外没有文字保存图片并插入
4HTML 最外层带 data-bake-markdown纯文本按 Markdown 插入
5纯文本去掉首尾空白后以 <svg 开头，并且能按 SVG 解析存成 assets/ 里的 .svg 文件，插入图片
6有 VS Code 的 vscode-editor-data语言为 markdown 时按第 8 条处理；为 plaintext 时按纯文本插入；其他语言插入带这个语言名的代码块
7有 HTML转换成 Markdown 后插入，见下文
8只有纯文本，并且出现块级 Markdown 写法按 Markdown 插入
9其他按纯文本插入
  • Mod-Shift-V 的判断：Chromium 中 Ctrl+Shift+V 触发的 paste 事件只有纯文本，无法从事件本身区分。编辑器在按键时记下这个快捷键，下一次 paste 读取后清除，按下其他键时也清除。
  • 第 3 条先于 HTML 检查。理由：浏览器「复制图片」时 HTML 只有一个 img 元素，应当插入文件；Excel 等表格软件同时提供表格 HTML 和单元格的图片，应当按表格处理。
  • 第 5 条先于第 6 条：从 VS Code 复制 SVG 源码时插入图片。需要代码块时，先输入三个反引号建代码块再粘贴，按第 1 条插入纯文本。
  • 块级 Markdown 写法指标题、列表、表格、公式块和用反引号或波浪号围栏写的代码块。缩进写法的代码块不算。理由：带缩进的普通文字会被误判成代码块。
  • 其他代码编辑器（JetBrains 等）只提供纯文本和带 <pre> 的 HTML，按第 7 条得到没有语言名的代码块。

所有来源都先转成 bake 格式的 Markdown，再由编辑器的严格解析器解析后插入。只有一个段落时，内容并入光标所在的段落；光标所在的段落为空时，粘贴的块替换这个空段落；有多个块时，光标所在的段落被拆开。表格单元格和组件作为整体插入，不与光标所在的块合并。粘贴的内容不符合结构规则时（例如卡片网格中直接写段落），把剪贴板的纯文本按换行分成段落插入，状态栏显示「粘贴的内容不符合结构规则，已按纯文本插入」。

粘贴网页的 HTML

标题、列表、链接、表格、代码块、加粗、斜体、高亮对应到编辑器格式，不认识的标签只保留文字。带 data-md 的元素直接使用它的值。远程图片被去掉，理由：bake 的图片必须在文章的 assets/ 中，远程地址会让构建报错。代码块的语言名从 language-* 类名读取，Shiki 不支持的语言名由构建报错。

网页里的公式按下表找到 TeX 源码，找不到时只保留公式的文字。

公式来源TeX 源码的位置独立公式的判断
bake 页面元素的 data-texclass 含 display
KaTeX.katex 内 TeX 格式的 annotation外层是 .katex-display，或 math[display="block"]
MathJax 4mjx-container 内的 mjx-math[data-latex]mjx-container[display="true"]
MathML（Wikipedia 等）math 内 TeX 格式的 annotation，没有时用 alttextmath[display="block"]

TeX 格式的 annotation 指 encoding 属性为 application/x-tex 的 annotation 元素。MathJax 3（CHTML 和 SVG 输出）复制得到的 HTML 既没有 TeX 也没有 MathML，这类公式无法还原。Chromium 复制 KaTeX 的行内公式时不带 annotation，这类公式也只保留文字。TeX 在 HTML 转换之前取出，理由：转换会合并空白，多行 TeX 中的换行和 % 注释会被破坏。

粘贴图片

  • 接受的类型：image/png、image/jpeg、image/gif、image/webp、image/avif、image/svg+xml，扩展名分别为 png、jpg、gif、webp、avif、svg。其他类型的文件忽略。
  • 图片通过 POST /__bake/asset 写入文章所在目录的 assets/，文件名是内容哈希的前 8 位加扩展名，例如 assets/3f9a1c2e.png。理由：同一张图片粘贴两次只保存一个文件。插入的图片说明文字为空。
  • 保存期间，插入位置显示「图片保存中…」，这个位置随编辑移动；保存完成后图片插在这个位置。图片独占一段：光标在段落中间时段落被拆开，位置在表格内时插在表格之后。多个文件按顺序插入，每张图片一个段落。
  • 保存失败时，状态栏显示「图片保存失败：」加英文的错误信息，已经保存成功的图片保留。

粘贴内容中的 id 和旁注名

  • 标题的 {#id}、段落的 ^block-id、独立公式的 \label{…} 与文档中已有的相同时去掉，标题改用生成的 id。理由：重复的 id 会让渲染报错。剪切后粘贴时原内容已经删除，id 保留。
  • 粘贴的旁注引用与文档中已有的引用同名时，新粘贴的引用和它的注释改用新名字，见上文旁注一节。

拖入

从编辑器之外拖入的内容按上表第 3 到 9 条处理，插入位置是放下的位置。编辑器内部的拖动由拖动手柄处理。

从编辑器复制

选区用保存时使用的同一个 Markdown 输出器转成文本，复制出去的内容和 .md 文件里的写法相同。选区在一个表格单元格或一个列表项内时，只输出其中的文字，不带表格或列表的外层；跨单元格选择时补上表格的外层，第一行作为表头。选区引用到的旁注，注释一起复制，放在引用它的段落之后。剪切与复制得到相同的内容，写入后删除选区。

从发布的页面复制

  • 加载：页面加载完成后，在浏览器空闲时加载复制脚本（copy-markdown.js）。加载完成之前的复制由浏览器默认处理。copy-markdown.js 不包含 Markdown 解析器，打包压缩后 gzip 不超过 16 KB，测试检查。
  • 范围：只处理选区在 <article> 内的复制；编辑器已经处理的复制、空选区不处理。选区在一个代码块内时，纯文本直接是选中的代码，不加围栏。
  • 选区的起点或终点在一个公式、组件或旁注内时，扩展到包含整个元素。
  • 完全选中的带 data-md 的元素（指令块、组件、旁注、带属性的标题、图片）直接使用 data-md；组件和旁注总是按完全选中处理。部分选中的指令块只转换选中的子元素，例如只选提示框中的一句时不带提示框。
  • 渲染生成的文字（标题的锚点、卡片标题、旁注编号、提示框标签、折叠块的标题）不进入复制结果。没有 data-md 的标题不写 {#id}，理由：这个 id 是生成的。
  • 站内链接以站点的 base 开头时去掉这个前缀，改回 / 开头的站内地址。
  • 选区中有旁注引用而对应的旁注不在选区内时，把旁注的原文加在引用所在的顶层块之后。
  • 独立的 HTML 块使用浏览器序列化后的 HTML，与原文可能不同（例如 <rect/> 变成 <rect></rect>），再次渲染的结果相同。

两种复制写入的 HTML 都放在 <div data-bake-markdown> 中。公式的 SVG 引用页面字形容器中的字形，复制时把引用到的字形放进 HTML 开头的一个隐藏的 <svg>，粘贴到其他网页编辑器时公式能显示。

公式在编辑器里怎么渲染

打开编辑器时，编辑器直接使用页面上已经渲染好的公式 SVG，不在浏览器里重新渲染。只有被修改的公式才在浏览器里用 MathJax 渲染，结果按 TeX 源码缓存，同一个公式只渲染一次。MathJax 只在第一次修改公式时加载。

编辑器和构建读取同一份 MathJax 配置（宏和字体），两边输出的 SVG 相同。保存写回文件时开发服务器不重新渲染页面，所以修改一个公式只引起这一个公式的渲染。新公式用到的字形加入页面上的 mathDefs。

带 \label 的编号公式和 \eqref 显示打开编辑器时的编号。新增或删除编号公式后，编号在关闭编辑器重新渲染页面时更新；编辑器之外修改文件导致重新载入时，编号按新内容重新计算。理由：编辑时重新编号会让后面所有编号公式重新渲染。
