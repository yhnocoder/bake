编辑器

编辑器运行在 bake dev 打开的页面上：点「编辑」后，排好版的页面本身变成可编辑的，修改自动写回 .md 文件。本文档写编辑器的界面、每种内容的编辑方式、保存与冲突、复制与粘贴，以及公式的渲染策略。

编辑器是什么样子

A. 页面顶部版式原有的标题区，标题直接输入。
B. 目录版式原有的目录，随标题实时更新。
C. 正文Milkdown 编辑区，样式与发布的页面相同。空行输入 / 打开插入菜单。
D. 状态栏右下角：「编辑」开关、「属性」按钮（编辑器打开时显示）、保存状态（已保存、保存中、冲突）。

右侧栏在编辑时显示旁注，旁注可以直接输入。属性面板打开时固定在窗口右上角，宽度与右侧栏相同，编辑器中的旁注隐藏；关闭面板后旁注恢复显示。打开方式见 属性面板。

A 区的标题直接输入。内置版式的标题是 header.mast > h1，在 <article> 之外：

  • 编辑器打开时，这个 h1 设为 contenteditable="plaintext-only"，关闭时去掉。博客版式没有 header.mast > h1 时，标题只能在页面属性中修改。
  • 按 Enter 或失去焦点时写回：文字去掉首尾空白后与 frontmatter 的 title 不同时，改写 title 所在的行，与页面属性使用同一个改写函数和同一种编辑步骤，Mod-Z 可以撤销。Enter 不插入换行，焦点回到正文。
  • 文字为空时恢复为当前的 title，不写回。按 Esc 恢复为当前的 title，焦点回到正文。
  • 页面属性修改 title、撤销或重做改变 title 时，标题区的文字随之更新。保存后页面外框被替换时，新的标题区同样设为可编辑。

编辑器只存在于 bake dev。bake build 的输出不包含编辑器代码，也不包含「编辑」按钮。

打开和关闭编辑器时发生什么

开发服务器在页面中加入编辑器入口模块 src/editor/index.js，它只负责「编辑」开关和状态栏。编辑器本身的代码在第一次点击「编辑」时才加载。点击「编辑」后：

  1. 请求 /__bake/source，取得文件原文和哈希值。
  2. 记下页面上已经渲染好的公式：<article> 中每个带 data-tex 的元素，按行内或独立加 TeX 源码记入一个表，见 公式在编辑器里怎么渲染。
  3. 解析原文。frontmatter 原文存为文档根节点的属性，修改 frontmatter 是一个普通的编辑步骤，可以撤销，与正文一起自动保存。
  4. 在 <article> 里创建编辑器，替换原有内容。<article> 的 class 和版式结构不变，所以编辑器的样式与页面相同。

文章违反内置块的结构规则，或者有编辑器无法原样保存的写法（例如行内 HTML、组件指令带方括号文字）时，编辑器不打开，<article> 保持阅读视图，状态栏显示「文章有结构错误，修正后才能编辑」。具体错误由开发服务器的错误列表给出。

再次点击「编辑」关闭编辑器：等待未完成的保存，再请求页面最新的渲染结果替换 <article> 的内容，然后在 window 上发出 bake:page-updated 事件，旁注位置等页面脚本据此重新计算。

块怎样变成编辑器节点

开发服务器提供虚拟模块 virtual:bake/registry。默认导出是块类型登记表和组件的属性表（每个组件的 static properties）；另外导出 layouts（{ 版式名: fields }）、themes（主题名列表）和 defaultTheme（bake.config.js 的 theme），供页面属性使用。编辑器按块的 form 生成节点：

块的 form编辑器节点
container块节点，内容是一个或多个块。指令方括号里的文字（例如 :::fold[推导细节] 的标题、:::callout[向量说明] 的名称）是第一个子节点，可以直接输入；折叠块必须有这个子节点，其他块的这个子节点删空后保存时不写方括号。render 显示名称的块（例如提示框）在编辑器里总有这个子节点，为空时显示默认名称（提示框为 kind 对应的「说明」「提示」「注意」）作为占位文字，点击名称把光标放进这个子节点。只含一个空段落的容器块保存为 :::callout 加 ::: 两行，不写空行
leaf块节点，内容是方括号里的行内文字
text行内格式（mark），方括号里的文字可以直接编辑

内置块的结构规则（见 内容格式）写进编辑器的 schema：导语只能是第一个块，卡片网格只含卡片，参考文献只含一个列表，出处只能在引用块末尾。插入、拖动和粘贴共用这一份约束，产生不符合规则的文档的操作不会执行。副标题必须紧跟标题，这条规则无法写进 schema，由一个检查函数判断。

节点的 DOM 由块定义的 render 生成，与页面上的 HTML 相同；render 输出中不属于内容的部分只显示，不能编辑。块和组件的属性存在节点上，原样写回。组件（指令名含 -）在编辑器里创建同名的 custom element，组件照常运行，<figcaption> 是可以输入的图题。

插入菜单

光标所在的段落全部内容是 / 加若干个非空白字符、并且光标在段落末尾时，光标下方显示插入菜单，/ 之后的文字是查询文字。在段落中间输入 / 不显示菜单。输入 / 后菜单立即显示，筛选结果随输入立即更新（@milkdown/plugin-slash 的显示延迟设为 0，它默认是 200ms）。菜单的定位由 @milkdown/plugin-slash 负责，筛选、键盘选择和插入由 bake 实现，菜单的 DOM 由 bake 生成。

  • 查询文字为空时列出全部可插入的项；不为空时只列出名字、显示文字或关键词包含查询文字的项，不区分大小写，保持原有顺序。没有匹配项时显示「没有匹配的项」，Enter 按普通回车处理。
  • ↑、↓ 移动高亮项，在两端循环；Enter 插入高亮项；鼠标点击插入该项。Esc 关闭菜单，/查询文字 留在段落里，之后再输入时菜单重新显示。
  • 段落内容不再符合上面的条件（例如输入了空格、删掉了 /）时菜单关闭。

菜单分「块」和「组件」两组，菜单项由块类型登记表和组件属性表生成，新增块类型或组件后不需要修改编辑器：

组项显示顺序
块块类型登记表中的块（内置块，再是博客块），:span 除外label 和 name，例如「提示框 callout」登记表顺序
「表格」「表格」，关键词 table块组的内置项之后
其他模块登记的项（例如链接选择器的「链接」）登记时给出的文字登记顺序
组件virtual:bake/registry 中的组件组件名，例如 demo-plot按名字排序

其他模块通过 Milkdown 的 ctx slice insertMenuItemsCtx（src/editor/insert-menu.js 导出）登记菜单项，每项为 { label, keywords, run(view, range) }，range 是 /查询文字 所在段落的位置 { from, to }，run 自己删除查询文字并插入内容。:span 不列出：它必须紧跟一个旁注引用，由旁注模块插入。

一个块类型、表格或组件只在当前位置允许插入时列出。判断只用 schema 和副标题的检查函数：

  1. 设 /查询文字 所在段落的父节点为 parent、序号为 index，parent.canReplaceWith(index, index + 1, nodeType) 为真。
  2. 把段落换成这个节点后，parent 通过副标题的检查函数。

所以导语只在正文的第一个块处列出，副标题只在标题之后列出，出处只在引用块的最后一段列出，表格单元格里只列出 text 形式的块。插入卡片网格时生成第一张卡片。text 形式的块只要求段落允许它的 mark。

段落不能是卡片网格的直接子节点，所以卡片另有一条规则：/查询文字 所在段落是卡片的直接子节点时列出卡片，新卡片插在当前卡片之后，/查询文字 从当前卡片中删除。

插入前删除 /查询文字，每种形式插入的内容和插入后光标的位置如下：

形式插入的内容光标
containercreateAndFill({ attributes: {} }) 创建的块节点，替换所在段落。必需的子节点由 schema 生成，例如折叠得到空标题和一个空段落，卡片网格得到一张带空段落的卡片；显示名称的块（提示框）带一个空的名称子节点第一个可以输入文字的位置；可以留空的名称子节点跳过，光标在第一个段落
leaf同上，内容为空块内
text段落内容替换为 label 文字，加上该块的 mark，属性为空选中这段文字，直接输入时替换文字并保留 mark
组件组件节点，属性为空，图题为空，替换所在段落图题内
表格@milkdown/preset-gfm 的 createTable 生成的 3 行 3 列表格，替换所在段落第一个单元格
  • 属性为空表示全部使用默认值，插入后的 Markdown 是 :::callout、::demo-plot 这样不带属性的写法。图题为空的组件写成 ::demo-plot，输入图题后写成 :::demo-plot 加图题。
  • 一次插入是一个事务，事务开始前调用 prosemirror-history 的 closeHistory，所以 Mod-Z 一步撤销插入，撤销后恢复 /查询文字。

属性面板

属性面板有两种内容：块属性（对象是一个节点或一段 mark）和页面属性（对象是 frontmatter）。可以作为块属性对象的内容和属性定义的来源：

内容属性定义的来源面板标题
组件组件的 static properties组件名
指令块（container、leaf），定义里的 attributes 不为空块定义的 attributes块的 label
text 形式的 mark，定义里的 attributes 不为空同上同上
标题src/format/attributes.js 的 headingAttributes：id（id）、toc（目录短标题）「标题」
图片src/format/attributes.js 的 imageAttributes：width（宽度）、height（高度）、float（环绕，none | left | right，默认 none）「图片」

打开面板的方式：

  • 点击节点内容区以外的部分：组件的绘图区（<figcaption> 以外的部分）、容器块的边框和不可编辑的部分（例如卡片的标题）、标题左侧的 id、图片。面板打开，对象是这个节点。点击块内的段落、提示框的名称或组件的图题时只移动光标。
  • 状态栏的「属性」按钮：面板关闭时打开，对象是光标所在位置最内层的可作为对象的内容；光标不在这样的内容里时显示页面属性。面板打开时再次点击关闭面板。
  • 面板右上角的「关闭」按钮，或焦点在面板内时按 Esc，关闭面板，焦点回到正文。

面板打开时，对象随选区变化：选区离开当前对象时，对象改为新选区所在位置最内层的可作为对象的内容，没有时显示页面属性。对象被删除（包括编辑器重新载入文件）时显示页面属性。理由：光标在块里输入时面板不会自动出现，旁注保持显示；打开面板后移动光标就能查看另一个块的属性。

面板是 <body> 下的一个元素，固定在窗口右上角，宽度为 --sidenote-width；内容超过窗口高度时面板内部滚动。没有右侧栏的版式（bento）和窗口宽度 1100px 以下时位置相同，盖在正文上方。面板的颜色只使用主题变量。面板打开时 <body> 有 class="properties-open"，编辑器中的旁注在这个 class 下隐藏。

控件按属性定义的 type 生成，属性名旁显示 label，没有 label 时显示属性名：

type控件写回的时机
number有 min 和 max 时为滑块加数字输入框，使用 min、max、step；缺少其中一个时只有数字输入框滑块：拖动中只更新组件元素，松开时写回；数字输入框：Enter 或失去焦点时写回
string单行输入框；标题的 id 为空时显示生成的 id 作为提示文字Enter 或失去焦点时写回
boolean开关切换时写回
enum下拉框，选项来自 options；没有 default 时第一个选项是「（未设置）」选择时写回
list（只用于版式字段）多行输入框，每行一项，空行忽略失去焦点时写回

写回的值：

  • 属性值等于 default 时，从 Markdown 中删除这个属性；frontmatter 中删除这个字段。理由：文件里只保留与默认值不同的属性，默认值修改后所有没有显式设置的地方一起生效。
  • 输入框清空、下拉框选「（未设置）」时，删除这个属性。
  • number 写成 String(Number(输入值))，例如输入 1.50 写成 1.5。
  • boolean 写成 key=true 或 key=false，等于 default 时不写。理由：与内容格式的校验（只接受 true、false）一致，default: true 的属性也能设成 false。
  • 写回前用内容格式模块的校验函数检查这一个值：标题和图片用 attributeError(kind, key, value)，指令和组件用 directiveAttributeError(name, key, value, properties)，frontmatter 字段用 fieldError(name, value, field)，与 parse 使用同一份代码。不合法时控件下方显示英文的错误说明，不写回。

每次写回是一个事务，事务开始前调用 closeHistory，Mod-Z 一步撤销一次修改。写回后由自动保存在 800ms 后保存，所以拖动滑块时文件在松开后写入。节点的属性用 tr.setNodeAttribute(pos, 'attributes', 新的属性对象) 修改；text 形式的 mark 在同一个事务里 removeMark 后 addMark。属性对象保留原有键的顺序，新增的键加在末尾；标题和图片的属性删空后不写花括号。

组件节点的属性变化时，编辑器不重新创建组件元素，只同步元素的属性，组件的 attributeChangedCallback 被调用，内部状态和图题保留。拖动滑块时面板直接对组件元素调用 setAttribute，组件实时重画，文档不变；组件节点视图忽略 contentDOM 以外的 DOM 变化，所以这次变化不会让 ProseMirror 重新读取节点。

页面属性

没有选中块时，属性面板显示页面属性，修改写回文件开头的 frontmatter。面板列出：

  • 通用字段，顺序为 title（标题）、slug（地址）、date（日期）、layout（版式）、theme（主题）、width（正文宽度）、draft（草稿），见 内容格式 的 frontmatter 一节。layout 是下拉框，选项是 virtual:bake/registry 的 layouts；theme 是下拉框，选项是 themes，默认值是 defaultTheme，所以选择站点默认主题时删除这个字段。
  • 小标题「版式字段」下列出当前版式的 fields。当前版式没有字段时不显示这一节。
  • 其他字段（例如 category、tags）不显示，原样保留。

frontmatter 的 YAML 有语法错误时，面板只显示 parse 给出的错误说明，不显示控件。字段的当前值不合法时，控件显示默认值，下方显示 fieldError 的说明。

frontmatter 原文存在文档根节点的 frontmatter 属性中，页面属性的修改是 tr.setDocAttribute('frontmatter', 新原文)，与正文的修改一样触发自动保存，可以撤销，重新载入和冲突处理使用同一套代码。新原文由 src/format/frontmatter.js 的两个函数按行改写：

setFrontmatterField(raw, name, value)  // → string
deleteFrontmatterField(raw, name)      // → string
  • 一个字段所占的行是从键所在的行到值结束的那一行，由 yaml 包的 parseDocument 找到顶层的同名键。
  • 修改已有字段时只重写这个字段所占的行，新内容是 yaml 包的 stringify({ [name]: value }, { lineWidth: 0 })：字符串需要时加引号，列表写成 - 项 的块形式，缩进 2 个空格。被重写的行的行尾注释随之删除。
  • 新增字段加在最后一行之后；删除字段时删除这个字段所占的行。
  • 其他行逐字节不变，包括注释、空行、引号写法和流式列表 [a, b]。原文末尾没有换行时，结果保持没有换行。

理由：内容格式规定 frontmatter 原文不变，bake format 不改写它。yaml 包的 Document.toString() 会改变没有修改的行（[GELU, SiLU] 变成 [ GELU, SiLU ]，折叠字符串重新排版），文件的 diff 会包含无关的行。按行改写后的原文仍是合法的 YAML，bake format 保持它不变。

修改 layout 时，在同一个事务里：

  1. 写入新的 layout；新值等于默认值 essay 时删除这个字段。
  2. 旧版式声明、新版式没有声明的字段，从 frontmatter 中删除。
  3. 两个版式都声明的同名字段（例如 essay 和 paper 的 toc、numbered），值通过新版式的 fieldError 检查时保留，否则删除；值等于新版式的默认值时也删除。

理由：文章使用其他版式的字段时构建报错，切换后留下的字段会让构建失败。删除的值可以用 Mod-Z 一步恢复，所以不弹出确认框。

修改 slug 后页面地址改变：/__bake/save 返回新地址，编辑器用 history.replaceState 改变浏览器地址；新 slug 已被另一篇文章使用时保存返回 400，状态栏显示「保存失败」和原因。slug 的格式由 fieldError 检查，格式不合法的值不会写入。

title、layout、theme、width 和版式字段决定 <article> 以外的页面结构和样式。保存成功、并且这次保存的 frontmatter 与上一次保存的不同时（比较 bake:editor-saved 事件的 detail.frontmatter），编辑器请求当前页面地址，用 DOMParser 解析开发服务器渲染的整页 HTML，调用 replaceChrome 替换 <article> 以外的页面结构和样式表，保留当前的 <article> 元素，编辑器不重新创建，然后在 window 上发出 bake:page-updated。滚动位置、焦点、属性面板和 <body> 上的 bake-editing、properties-open 保持不变。

怎样移动块

鼠标移到一个块上时，块的左侧显示拖动手柄 ⋮⋮。按住手柄拖动，目标位置显示一条横线，松开后块移到横线处。点击手柄打开块菜单，菜单里有「删除」「复制一份」「上移」「下移」。

  • 可以拖动的块：段落、标题、列表项、引用、代码块、公式块、图片、组件、表格、独立的 HTML 块和所有容器块。容器块连同里面的内容一起移动。
  • 块可以拖进或拖出容器块，例如把一个段落拖进提示框，或者把卡片网格里的一张卡片拖到另一个位置。拖进容器后不符合容器结构的位置不显示横线，例如卡片网格里只能放卡片。
  • 移动带旁注编号的段落时，旁注跟着段落移动，编号按新的顺序重新计算。
  • 键盘操作：Mod-Shift-↑ 和 Mod-Shift-↓ 把光标所在的块上移或下移一个位置。
  • 移动可以用 Mod-Z 撤销，一次移动对应一步撤销。
  • 块移动时使用 Motion 动画，其他块让出位置的过程也有过渡；系统开启减少动态效果时直接移动。

拖动使用 Milkdown 的 block 插件（@milkdown/kit/plugin/block）提供的手柄定位和 ProseMirror 原生的节点拖放。

旁注怎么编辑

  • 在正文中按 Mod-Alt-F 或输入 [^，在光标处插入一个新编号，右侧栏出现一条空注释，光标移到注释里。
  • 注释是编辑器文档中的一个块，可以输入段落、公式、链接和列表。
  • 删除正文里的编号时，对应注释一起删除；撤销时一起恢复。
  • 编号随增删实时更新。
  • 编辑器和发布的页面使用同一份对齐代码，见 内容格式中旁注的排版。
  • 保存时注释定义写在引用它的段落之后。已有的脚注名保持不变；新插入的注释命名为 [^n1]、[^n2]，跳过文件中已经使用的名字。

站内链接怎么插入

按 Mod-K 或在插入菜单选择「链接」，在光标下方打开链接选择器。选择器每次打开时请求开发服务器的 /__bake/sections，见 构建与开发服务器，所以新加的标题和段落也能找到。

  • 候选是全站的文章、标题和带 ^block-id 的段落，每一项显示种类（文章、标题、段落）、文字和目标：文章的目标是页面地址，标题和段落的目标是所在文章的标题加 #id。
  • 输入为空时按页面顺序列出，当前文章的标题和段落排在最前。输入不为空时按不区分大小写的子串匹配，分三档：文字以输入开头，文字包含输入，id 或页面地址包含输入。同一档内文章在前、标题其次、段落最后，再按页面顺序。最多显示 20 项。
  • ↑、↓ 移动选中项，Enter 确认，Esc 或点击选择器外部关闭，关闭后焦点回到编辑器。
  • 地址的写法：目标在当前文章时写 #id；其他文章写不带末尾 / 的页面地址，有 id 时加 #id，例如 /features#chain-rule，首页写 /。与 内容格式中站内引用的写法 一致。
  • 输入以 http:// 或 https:// 开头时，Enter 把输入作为外部链接插入。
  • 有选区时给选区加链接，文字不变。没有选区时在光标处插入链接文字：文章用文章标题，标题用标题文字，段落用所在文章的标题，外部链接用地址本身。理由：规则简单，作者通常会改写。
  • 光标在已有链接上时，输入框填入这个链接的地址，选择后修改这个链接的地址；清空输入框后按 Enter 去掉链接，文字保留。
  • 每次插入或修改是一步，Mod-Z 一步撤销。

编辑器里鼠标停留在站内链接上同样显示预览卡片，与阅读模式使用同一段代码，内容来自开发服务器的 /__bake/preview，所以编辑器里的链接可以使用 Markdown 中的原始地址。

修改怎么保存

  1. 每次修改后等待 800ms，期间没有新的修改时保存。
  2. 编辑器用 Markdown 输出器把整篇文档转成文本，连同载入时文件内容的哈希值发给 POST /__bake/save。
  3. 开发服务器比较磁盘上文件的哈希值。相同时写入文件，返回新的哈希值；不同时不写入，返回冲突。
  4. 保存成功后状态栏显示「已保存」。开发服务器识别出这次文件变化来自编辑器，不重新渲染页面，也不通知页面更新。
  5. 修改 slug 后页面地址改变，开发服务器返回新地址，编辑器改变浏览器地址，之后的请求使用新地址。
  6. 编辑器在 window 上发出 bake:editor-saved 事件，detail 为 { url, hash, frontmatter }，页面外框据此更新。

状态栏显示「已保存」「保存中」「保存失败」或「冲突」。保存失败或冲突时，状态栏显示原因，编辑器保留当前内容，不丢弃修改。冲突时状态栏提供两个按钮：「使用磁盘上的版本」用磁盘上的内容重新载入编辑器；「保留我的修改并覆盖」用磁盘内容的哈希值重新保存编辑器的内容。

在编辑器之外修改文件时会怎样

情况结果
编辑器未打开，.md 被修改页面就地替换正文、目录和旁注，滚动位置保持不变，不刷新整页

复制与粘贴怎么处理

粘贴进编辑器的内容自动转换成对应的格式。从编辑器或发布的页面复制出去时，剪贴板的纯文本是 Markdown，同时附带 HTML，粘贴到支持格式的应用时保留格式。

粘贴进编辑器

来源剪贴板内容转换结果
bake 生成的页面HTML，元素上带 data-tex 和 data-md与原文相同的公式、组件、旁注和块
其他网页HTML标题、列表、链接、表格、代码块、加粗、斜体对应到编辑器格式；不认识的标签只保留文字
网页里的公式MathJax 或 KaTeX 输出中的 TeX 源码，或 MathML公式
VS Code 等代码编辑器纯文本和 vscode-editor-data 中的语言名带语言名的代码块

Excel、Numbers、Google SheetsHTML 表格GFM 表格
截图、图片文件、SVG 文件图片数据文件存进文章所在目录的 assets/，插入图片
SVG 源码以 <svg 开头的文本存成 assets/ 里的 .svg 文件，插入图片

纯文本按 Markdown 解析的条件：文本中出现 Markdown 的块级写法（标题、列表、表格、代码块、公式块）。不满足时按普通文本插入。按 Mod-Shift-V 始终按普通文本插入。

粘贴的图片文件名是内容哈希的前 8 位加原扩展名，例如 assets/3f9a1c2e.png。理由：同一张图片粘贴两次只保存一个文件。图片通过 POST /__bake/asset 写入。

复制出去

  • 编辑器里：选区用保存时使用的同一个 Markdown 输出器转成文本，复制出去的内容和 .md 文件里的写法相同。
  • 发布的页面：页面空闲时加载复制脚本，拦截 copy 事件，把选区的 HTML 转回 Markdown。构建时给公式加 data-tex，给组件、旁注和指令块加 data-md（该元素对应的 Markdown 源码），转换时直接使用这些属性。选区只包含公式或组件的一部分时，按整个元素处理。

公式在编辑器里怎么渲染

打开编辑器时，编辑器直接使用页面上已经渲染好的公式 SVG，不在浏览器里重新渲染。只有被修改的公式才在浏览器里用 MathJax 渲染，结果按 TeX 源码缓存，同一个公式只渲染一次。MathJax 只在第一次修改公式时加载。

编辑器和构建读取同一份 MathJax 配置（宏和字体），两边输出的 SVG 相同。保存写回文件时开发服务器不重新渲染页面，所以修改一个公式只引起这一个公式的渲染。新公式用到的字形加入页面上的 mathDefs。

带 \label 的编号公式和 \eqref 显示打开编辑器时的编号。新增或删除编号公式后，编号在关闭编辑器重新渲染页面时更新；编辑器之外修改文件导致重新载入时，编号按新内容重新计算。理由：编辑时重新编号会让后面所有编号公式重新渲染。
