构建与开发服务器

本文档写 bake 的命令、配置文件、页面地址规则、bake build 的输出，以及 bake dev 提供的接口和不刷新整页的更新方式。

有哪些命令

命令作用退出码
bake new <path>新建 content/<path>.md，frontmatter 只有 title 和 slug 两项：title 是 <path> 的最后一段，slug 等于 <path>。<path> 不符合 slug 的格式时报错。成功时输出 Created content/<path>.md；文件已存在时输出 content/<path>.md already exists0 成功，1 失败
bake dev [--port 4321]启动开发服务器，默认端口 4321，被占用时依次尝试下一个端口运行中不退出
bake build [--out dist]生成静态网站到 dist/，--out 改变输出目录。成功时最后一行输出 Built N pages to dist/（N 为 1 时是 Built 1 page to dist/）0 成功，1 有错误
bake format [path...]把 .md 文件统一成编辑器的输出格式，不改变内容。没有路径时处理 content/ 下全部 .md，跳过 notes/、components/、assets/。每改写一个文件输出一行路径，最后一行输出 Rewrote N files（N 为 1 时是 Rewrote 1 file）或 No files to rewrite。只检查 Markdown 语法和 frontmatter 的 YAML 语法，有错误的文件不写回，按错误格式输出0 成功，1 有解析错误

所有命令在博客仓库根目录运行，从当前目录读取 bake.config.js。命令行的全部输出使用英文，包括错误说明。错误信息的格式是 文件路径:行:列 错误说明，便于编辑器跳转。

$ bake build content/word2vec/index.md:42:18 Link points to a missing id /matrix-calculus/deep-learning/#chain-rul 1 content/bpe/index.md:7:1 Unknown directive :::callot 2 errors, dist/ was not written 2
  1. 每个错误一行，构建继续检查其余文件，最后一行汇总错误数，1 个错误时写 1 error。
  2. 站点本身有错误时（bake.config.js 不能载入、组件不能读取、主题不存在、slug 重复），只输出这些错误，不渲染页面。理由：配置和组件的错误会让很多页面报出由它引起的错误，例如配置中的宏缺失后每个用到它的公式都报错。
  3. 有任何错误时不写入输出目录，已有的 dist/ 保持不变。没有错误时先写到输出目录旁的临时目录，完成后替换输出目录。

配置文件有哪些字段

export default {
  title: 'Learn by Visualization',
  base: process.env.BASE_PATH ?? '/',
  theme: 'blue',
  math: { macros: { R: '\\mathbb{R}' } },
  site: {
    categories: [{ id: 'math', name: '数学', color: '#985b57' }],
  },
};
字段默认值作用
title必填站点名，用于 <title> 后缀和版式页头
base/站点部署的路径前缀。站内链接在 Markdown 中写不带前缀的绝对路径，构建时加上前缀
theme无，必填文章未写 theme 时使用的主题，必须是 themes/ 中的文件名，否则报错
math.macros{}MathJax 宏，构建和编辑器共用
site{}bake 不解释的数据，原样提供给组件，见 扩展接口

页面地址怎么确定

页面地址由 frontmatter 的 slug 决定，与文件在 content/ 中的位置无关，文件可以任意移动。slug 必填，由一段或多段组成，段之间用 / 分隔，每段只含小写字母、数字和 -。地址是 /<slug>/，首页写 slug: /，地址是 /。

文件slug地址输出文件
content/index.md//dist/index.html
content/word2vec/index.mdword2vec/word2vec/dist/word2vec/index.html
content/matrix-calculus/deep-learning.mdmatrix-calculus/deep-learning/matrix-calculus/deep-learning/dist/matrix-calculus/deep-learning/index.html
  • 两篇文章的 slug 相同时报错，错误列出两个文件。
  • slug 缺失或不合法时报错，这篇文章没有地址。
  • 站内链接写地址，例如 /matrix-calculus/deep-learning#chain-rule，所以移动文件不影响链接。站内链接可以写成带或不带末尾 / 的地址，构建时统一成带 / 的形式。
  • notes/、components/、assets/ 目录和以 _ 开头的文件不生成页面。
  • 地址的计算集中在 src/site/pages.js，构建和开发服务器都使用它。

bake build 输出什么

dist/
├── index.html
├── matrix-calculus/deep-learning/
│   ├── index.html            整页 HTML，公式已是 SVG
│   └── sections.json         这一页的标题小节和带 id 段落的 HTML，供悬停预览
├── assets/
│   ├── matrix-calculus/deep-learning/neuron.6b1f.webp
│   ├── themes/blue.D2fT0aQe.css
│   ├── client/page.Cw7nR1xA.js
│   ├── components/gradient-figure.Bq3x9LkT.js
│   └── bake.C8kya0lP.css
└── site.json                 全站页面列表：地址、标题和 frontmatter
  • 每个页面只加载正文中用到的组件脚本。组件、版式 CSS 和主题 CSS 由 Vite 打包，文件名带 8 位内容哈希（Vite 的哈希最短 6 位）。几个组件共用的代码由 Vite 拆到 assets/chunks/。
  • 图片由 sharp 处理：PNG 和 JPEG 转成 WebP；PNG、JPEG、WebP、AVIF 宽度超过 1600px 的缩到 1600px；GIF 和 SVG 原样复制。理由：GIF 可能是动图，转换会丢失动画。
  • 图片输出到 assets/<slug>/<文件名>.<哈希>.<扩展名>，哈希是源文件内容 SHA-256 的前 4 位十六进制。按 slug 分目录，所以移动文章文件不改变图片地址。
  • 每张图片输出 width 和 height 属性防止加载时页面跳动，并加 loading="lazy"。文章里写了 width 或 height 时，这两个值写进 style。
  • 构建缓存渲染结果，缓存放在 node_modules/.cache/bake/。缓存键是文章内容、渲染参数（配置、组件属性、版式字段、主题名）和渲染代码三者的 SHA-256。渲染代码的哈希由 bake 的 src/render/、src/format/、src/blocks/ 的文件内容、package-lock.json，以及博客 blocks/ 和 layouts/ 下全部文件的内容计算，修改 bake 源码、升级依赖或修改博客的块类型和版式后缓存失效；组件文件不参与计算，组件影响渲染的只有 static properties，已经在渲染参数中；渲染参数变化时缓存也失效，例如新加一个组件后，之前报告“未知组件”的文章会重新渲染。只修改一篇文章时，其他文章不重新渲染公式。缓存读写失败时直接重新渲染，不报错。构建成功后删除这次没有用到的缓存文件。

悬停预览的数据怎么生成

构建时为每个页面写一个 sections.json：

{
  "title": "深度学习中的矩阵微积分",
  "lede": "<p>...</p>",
  "sections": {
    "chain-rule": { "kind": "heading", "html": "<h2>...</h2><p>...</p>", "components": ["gradient-figure"] },
    "chain-rule-def": { "kind": "block", "html": "<p>...</p>", "components": [] }
  }
}
  • lede 是导语块的 HTML，没有导语时为空字符串。
  • 标题小节（kind 为 heading）的范围是从这个标题到下一个同级或更高级标题之前的正文。
  • 带 ^block-id 的段落（kind 为 block）的范围是这个段落本身。
  • components 是这段 HTML 中用到的组件名。
  • 生成函数在 src/build/sections.js，输入是渲染得到的正文 HTML，开发服务器的悬停预览也使用它。

页面上的预览脚本在鼠标停留在站内链接上 300ms 后请求目标页的 sections.json，结果按页面缓存。预览卡片中用到的组件按 components 列表加载。预览卡片里的链接不再弹出下一层预览。鼠标离开链接和卡片 200ms 后卡片关闭。

站内链接怎么检查

构建先渲染全部页面，收集每页的标题 id 和 ^block-id，再检查全部站内链接。链接指向不存在的页面、标题或段落时报错。同一页内出现重复的 id 时报错。bake dev 在页面上用状态栏提示断开的链接，不阻止页面显示。

bake dev 提供什么

开发服务器是一组 Vite 插件，只监听 localhost。启动后输出一行地址：

$ bake dev Local: http://localhost:4321/

请求页面地址时即时渲染对应的 .md，渲染结果按文件内容的 SHA-256 缓存。页面加载 Vite 的客户端、页面端更新脚本和正文用到的组件。草稿页面照常显示。页面不存在时返回 404 和一行说明。渲染有错误时页面照常显示，错误按 文件路径:行:列 错误说明 输出到终端；页面右下角的状态栏显示渲染错误数和断开的站内链接数，点击后展开列表。状态栏还可以显示一条与保存状态无关的提示，例如「图片保存失败」，下一条提示出现或点击关闭时移除。文章里的 ./assets/ 按文章所在目录提供。/site.json 返回当前的站点数据，内容与构建输出的 site.json 相同，组件从 bake/runtime 导入的 site 在开发服务器中从这里读取。Vite 预打包依赖的缓存放在系统临时目录的 bake-vite/ 下，按博客目录区分，开发服务器不在博客目录里写入文件。

接口的请求和返回都是 JSON，哈希是文件字节的 SHA-256 十六进制。出错时返回 { error }，error 是英文说明。

接口请求返回
GET /__bake/source?page=/word2vec/页面地址{ path, markdown, hash }：文件路径、Markdown 原文、哈希
POST /__bake/save{ page, markdown, hash }，hash 是载入时的哈希磁盘上文件的哈希等于 hash 时写入，返回 { hash, url }：新的哈希和页面地址；不等时不写入，返回 409 和磁盘上的版本 { markdown, hash }；新内容的 slug 已被另一篇文章使用时不写入，返回 400
POST /__bake/asset{ page, data, ext }，data 是 base64写入文章所在目录的 assets/<哈希前 8 位>.<ext>，返回 { path: './assets/3f9a1c2e.png' }；同名文件已存在时不重复写入
GET /__bake/sections无全站文章、标题、带 id 段落的列表，供链接选择器使用。由站内引用预览实现
GET /__bake/preview?href=/a/b/#id站内链接目标内容的 HTML，供编辑器里的悬停预览。由站内引用预览实现
  • ext 只接受 内容格式 列出的图片扩展名，其他返回 400。缺少字段或请求不是 JSON 时返回 400，页面地址不存在时返回 404。
  • 接口把 page 和文件路径解析成绝对路径后检查是否在 content/ 内，不在时返回 403。
  • /__bake/save 写入的内容改变了 slug 时，开发服务器在返回之前更新地址表，返回的 url 是新地址，编辑器之后的请求使用它。slug 格式不合法时照常写入，错误由渲染报告，这篇文章继续使用原地址，返回的 url 也是原地址。
  • 开发服务器的 Vite 插件在 api 字段提供 renderedPage(url) 和 componentEntry(name)，供其他功能的接口使用：前者返回这个地址使用缓存的渲染结果 { path, page, html, toc, mathDefs, components, messages }，地址不存在时返回 null；后者返回组件入口模块的地址，与页面加载组件时使用的地址相同。

文件变化怎么通知页面

  • .md 文件变化时，开发服务器重新渲染这一页，通过 Vite 的 WebSocket 发送 bake:page 事件，内容是 { url, html, toc, mathDefs, chrome, errors }：正文 HTML、目录、公式字形、<article> 以外的结构（包括目录）是否变化、渲染错误。.md 文件新增或删除时更新地址表；修改时只重新读取这个文件的 frontmatter。
  • 断开的站内链接在页面返回之后检查：检查带 #id 的跨页链接需要渲染目标页面，页面的首次载入不等待它。检查结果通过 bake:status 事件 { url, errors, links } 更新状态栏，在页面端更新脚本连接时和每次 bake:page 之后发送。
  • 变化来自 /__bake/save 时，开发服务器记录写入内容的哈希，监视到哈希相同的变化时不发送事件。
  • .md 文件新增、删除或 frontmatter 修改后，开发服务器重新计算站点数据，与上次发送的不同时发送 bake:site 事件，内容与 site.json 相同。bake.config.js 的 site 字段变化时同样发送。
  • 组件 .js 修改时由 Vite 的模块热更新处理，见 扩展接口；开发服务器同时重新读取它的 static properties，与修改前不同时重新渲染所有打开的页面，相同时不重新渲染。组件文件新增或删除时重新发现扩展并重新渲染所有打开的页面。
  • blocks/、layouts/ 下的文件（包括子目录中被导入的模块）新增、删除、修改，或 bake.config.js 变化时，重新发现扩展，重新渲染所有打开的页面并发送带 chrome: true 的 bake:page。页面端更新脚本连接时发送 bake:open，告诉开发服务器打开了哪个页面。
  • themes/ 下的文件变化时，开发服务器重新检查主题变量并更新状态栏，样式表由 Vite 替换；bake 的 CSS 变化时也由 Vite 替换样式表。主题因为缺少变量变得不可用、补全后重新可用，或主题文件新增、删除时，开发服务器重新渲染所有打开的页面并发送带 chrome: true 的 bake:page，由它替换样式表，Vite 不处理这次变化。理由：Vite 替换样式表时等待新样式表载入，替换期间样式表被移除会使之后的热更新消息都不再处理。
  • 扩展的错误按 文件路径:行:列 错误说明 输出到终端，并计入每个页面状态栏的错误列表，见 扩展出错时会怎样。

页面端更新脚本收到当前页面的 bake:page 后：

  1. 更新状态栏，在 window 上派发可取消的 bake:page-update，detail 是事件内容。编辑器打开时由编辑器处理并取消这个事件。
  2. chrome 为 true 时（版式、frontmatter、配置或目录改变），请求当前页面的整页 HTML，替换标题、样式表和 <article> 以外的结构，目录的结构由版式决定，所以也在这一步替换。当前的 <article> 元素放进新结构，不重新创建。理由：编辑器挂载在 <article> 上，重新创建会关闭编辑器。
  3. 事件没有被取消时替换 <article> 的内容，向页面的字形容器加入新的公式字形，已有的字形保留。
  4. 恢复滚动位置，派发 bake:page-updated，旁注脚本据此重新对齐。整个过程不刷新整页。
