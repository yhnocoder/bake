构建与开发服务器

本文档写 bake 的命令、配置文件、页面地址规则、bake build 的输出，以及 bake dev 提供的接口和不刷新整页的更新方式。

有哪些命令

命令作用退出码
bake new <path>新建 content/<path>.md，只含 title 一项 frontmatter；文件已存在时报错0 成功，1 失败
bake dev [--port 4321]启动开发服务器，默认端口 4321，被占用时依次尝试下一个端口运行中不退出
bake build [--out dist]生成静态网站到 dist/0 成功，1 有错误
bake format [path...]把 .md 文件统一成编辑器的输出格式，不改变内容。没有路径时处理 content/ 下全部 .md，跳过 notes/、components/、assets/。每改写一个文件输出一行路径，最后一行输出 Rewrote N files（N 为 1 时是 Rewrote 1 file）或 No files to rewrite。只检查 Markdown 语法和 frontmatter 的 YAML 语法，有错误的文件不写回，按错误格式输出0 成功，1 有解析错误

所有命令在博客仓库根目录运行，从当前目录读取 bake.config.js。命令行的全部输出使用英文，包括错误说明。错误信息的格式是 文件路径:行:列 错误说明，便于编辑器跳转。

$ bake build content/word2vec/index.md:42:18 Link points to a missing heading /matrix-calculus/deep-learning#chain-rul 1 content/bpe/index.md:7:1 Unknown directive :::callot 2 errors, dist/ not written 2
  1. 每个错误一行，构建继续检查其余文件，最后汇总报告。
  2. 有任何错误时不写入输出目录，已有的 dist/ 保持不变。

配置文件有哪些字段

export default {
  title: 'Learn by Visualization',
  base: process.env.BASE_PATH ?? '/',
  theme: 'blue',
  math: { macros: { R: '\\mathbb{R}' } },
  site: {
    categories: [{ id: 'math', name: '数学', color: '#985b57' }],
  },
};
字段默认值作用
title必填站点名，用于 <title> 后缀和版式页头
base/站点部署的路径前缀。站内链接在 Markdown 中写不带前缀的绝对路径，构建时加上前缀
theme无，必填文章未写 theme 时使用的主题
math.macros{}MathJax 宏，构建和编辑器共用
site{}bake 不解释的数据，原样提供给组件，见 扩展接口

页面地址怎么确定

页面地址由 frontmatter 的 slug 决定，与文件在 content/ 中的位置无关，文件可以任意移动。slug 必填，由一段或多段组成，段之间用 / 分隔，每段只含小写字母、数字和 -。地址是 /<slug>/，首页写 slug: /，地址是 /。

文件slug地址输出文件
content/index.md//dist/index.html
content/word2vec/index.mdword2vec/word2vec/dist/word2vec/index.html
content/matrix-calculus/deep-learning.mdmatrix-calculus/deep-learning/matrix-calculus/deep-learning/dist/matrix-calculus/deep-learning/index.html
  • 两篇文章的 slug 相同时报错，错误列出两个文件。
  • slug 缺失或不合法时报错，这篇文章没有地址。
  • 站内链接写地址，例如 /matrix-calculus/deep-learning#chain-rule，所以移动文件不影响链接。站内链接可以写成带或不带末尾 / 的地址，构建时统一成带 / 的形式。
  • notes/、components/、assets/ 目录和以 _ 开头的文件不生成页面。
  • 地址的计算集中在 src/site/pages.js，构建和开发服务器都使用它。

bake build 输出什么

dist/
├── index.html
├── matrix-calculus/deep-learning/
│   ├── index.html            整页 HTML，公式已是 SVG
│   └── sections.json         这一页的标题小节和带 id 段落的 HTML，供悬停预览
├── assets/
│   ├── matrix-calculus/neuron.6b1f.webp
│   ├── components/gradient-figure.a3c9.js
│   └── bake.d07e.css
└── site.json                 全站页面列表：地址、标题和 frontmatter
  • 每个页面只加载正文中用到的组件脚本。组件、版式 CSS 和主题 CSS 由 Vite 打包，文件名带内容哈希。
  • 图片由 sharp 处理：PNG 和 JPEG 转成 WebP；PNG、JPEG、WebP、AVIF 宽度超过 1600px 的缩到 1600px；GIF 和 SVG 原样复制。理由：GIF 可能是动图，转换会丢失动画。
  • 每张图片输出 width 和 height 属性防止加载时页面跳动，并加 loading="lazy"。文章里写了 width 或 height 时，这两个值写进 style。
  • 构建按文件内容缓存渲染结果，缓存放在 node_modules/.cache/bake/。只修改一篇文章时，其他文章不重新渲染公式。

悬停预览的数据怎么生成

构建时为每个页面写一个 sections.json：

{
  "title": "深度学习中的矩阵微积分",
  "lede": "<p>...</p>",
  "sections": {
    "chain-rule": { "kind": "heading", "html": "<h2>...</h2><p>...</p>", "components": ["gradient-figure"] },
    "chain-rule-def": { "kind": "block", "html": "<p>...</p>", "components": [] }
  }
}

页面上的预览脚本在鼠标停留在站内链接上 300ms 后请求目标页的 sections.json，结果按页面缓存。预览卡片中用到的组件按 components 列表加载。预览卡片里的链接不再弹出下一层预览。鼠标离开链接和卡片 200ms 后卡片关闭。

站内链接怎么检查

构建先渲染全部页面，收集每页的标题 id 和 ^block-id，再检查全部站内链接。链接指向不存在的页面、标题或段落时报错。同一页内出现重复的 id 时报错。bake dev 在页面上用状态栏提示断开的链接，不阻止页面显示。

bake dev 提供什么

开发服务器是一组 Vite 插件。请求页面时即时渲染对应的 .md，渲染结果按文件内容缓存。

接口请求返回
GET /__bake/source?page=/word2vec/页面地址文件路径、Markdown 原文、内容哈希
POST /__bake/save页面地址、新的 Markdown、载入时的哈希新的哈希；磁盘内容已变化时返回 409 和磁盘上的版本
POST /__bake/asset页面地址、文件数据、扩展名写入后的相对路径，例如 ./assets/3f9a1c2e.png
GET /__bake/sections无全站文章、标题、带 id 段落的列表，供链接选择器使用
GET /__bake/preview?href=/a/b/#id站内链接目标内容的 HTML，供编辑器里的悬停预览

写入类接口只接受 content/ 目录内的路径，路径解析后不在 content/ 内时返回 403。开发服务器只监听 localhost。

文件变化怎么通知页面

  • .md 文件变化时，开发服务器重新渲染这一页，通过 Vite 的 WebSocket 发送 bake:page 事件，内容是新的正文 HTML、目录和旁注。页面就地替换，不刷新整页。
  • 变化来自 /__bake/save 时，开发服务器记录写入内容的哈希，监视到哈希相同的变化时不发送事件。
  • 组件 .js 变化时由 Vite 的模块热更新处理；主题 CSS 变化时由 Vite 替换样式表。
  • 版式、blocks/ 或 bake.config.js 变化时，重新渲染所有打开的页面并发送 bake:page 事件。
