内容格式

本文档定义 bake 接受的 Markdown 写法：基础语法、内置块类型、公式、旁注、站内引用和 frontmatter。渲染模块和编辑器都从内容格式模块取定义，这里写下的每一种写法，在编辑器里都能编辑，在页面上都能显示。

写法只有一套来源：src/format/ 的 remark 插件组合和块类型登记表。新增一种写法时，先在这里登记，渲染和编辑器同时获得它。

基础语法是什么

正文是 CommonMark 加 GFM（表格、删除线、任务列表、脚注），再加公式（remark-math）、指令块（remark-directive）和文字标记 ==文字==。不认识的指令名在构建和编辑器载入时报错，报错信息包含文件路径和行号。

remark 插件提供的写法
remark-gfm表格、删除线、任务列表、脚注（用作旁注）
remark-math行内公式 $...$、独立公式 $$...$$
remark-directive:name[]{}、::name[]{}、:::name 三种指令
高亮插件==文字==。候选是 remark-highlight-mark 和 remark-flexible-markers，实现时按与 Milkdown 的兼容性选定；都不兼容时写一个 micromark 扩展

段落里能不能写 HTML

不能。段落、标题、列表里出现 HTML 标签时构建报错。只用一次的特殊内容写成独立的 HTML 块：前后各空一行，块内是完整的 HTML。编辑器里显示它的渲染结果，点开后编辑源码。

同一种写法用到第二次时，把它做成块类型或文字标记：所有博客都可能用到的加进 bake 的 src/blocks/，只有一个博客使用的加在该博客的 blocks/。理由：HTML 在编辑器里只能按源码编辑，块类型才能在编辑器里直接输入。

公式怎么写

行内公式写 $...$，独立公式写 $$...$$，独立公式可以用 \label{eq:name} 编号，正文用 \eqref{eq:name} 引用。全站共用的宏写在 bake.config.js 的 math.macros，构建和编辑器读取同一份配置。

构建时公式渲染成 SVG，页面不加载 MathJax。每个公式的元素带 data-tex 属性保存 TeX 源码，用于复制，见 编辑器 的复制与粘贴一节。组件内部需要在浏览器里渲染公式时，组件类声明 static runtimeMath = true，bake 只在用到这个组件的页面加载 MathJax。

旁注怎么写

旁注是带编号的注释：正文里显示上标数字，注释放在右侧栏，与引用处对齐。写法是 GFM 脚注，注释里可以写任意 Markdown，包括公式、链接、列表和多个段落。

导数描述的是函数在一点附近的变化率[^d]。

[^d]: 这里的“附近”指 $\Delta x \to 0$ 的极限，见[前文](#derivative)。

    注释的第二段缩进四个空格。
  • 编号按引用在正文中出现的顺序从 1 开始生成。[^d] 里的名字只用于对应，不显示。
  • 鼠标移到注释上时，正文里被注释的内容高亮；鼠标移到正文的编号上时，对应注释高亮。默认高亮编号所在的整个段落。
  • 需要精确范围时写 :span[被注释的文字][^d]，只高亮方括号里的文字。
  • 定义了但没有被引用的注释，以及引用了但没有定义的注释，构建报错。
  • 编辑器保存时，注释定义写在引用它的段落之后。理由：读源码时注释和正文挨在一起，往返测试也依赖这个固定位置。

生成的页面里，每条注释输出为 <aside class="sidenote">，放在引用它的段落之后。对齐和高亮的行为见 旁注怎么排版。

旁注怎么排版

CSS 把 .sidenote 放进右侧栏，没有脚本时注释也在段落旁边显示。对齐脚本只做两件事：

  1. 一次读取全部编号的纵向位置，再一次写入全部注释的位置。一条注释的顶部低于上一条注释的底部加 12px 间距时，按编号位置放置；否则往下推到上一条注释底部加 12px。
  2. 字体加载完成（document.fonts.ready）、正文容器尺寸变化（ResizeObserver）、折叠块展开或收起时，重新执行第 1 步。

读和写分成两批。理由：交替读写会让浏览器对每条注释都重新计算一次布局。

高亮使用 CSS Custom Highlight API：把被注释的文字范围登记为一个 Highlight，由 ::highlight(sidenote) 设定背景色。这个方式不修改 DOM，高亮不会引起重新排版。浏览器不支持这个 API 时不显示高亮，其他功能不受影响。

窗口宽度小于 1100px 时没有右侧栏，注释显示在所在段落之后，缩进并用小字号。窄屏上点编号展开注释的交互属于手机适配，不在第一版。

站内引用怎么写

站内链接就是普通 Markdown 链接，不加新语法。链接到站内页面时，鼠标停留在链接上会弹出预览卡片，显示目标内容。

这里用到的是[链式法则](/matrix-calculus/deep-learning#chain-rule)。

链式法则把复合函数的导数写成各层导数的乘积。 ^chain-rule-def
链接目标写法预览显示
一篇文章/topic/page标题和导语
一个标题/topic/page#heading-id这个标题下的整节，到下一个同级或更高级标题为止
一个段落/topic/page#block-id，段落末尾写 ^block-id这个段落
  • ^block-id 是 Obsidian 的块引用写法，写在段落最后，前面有一个空格，页面上不显示。它在页面上成为段落的 id。
  • 站内链接指向的文章、标题或段落不存在时，构建报错，报错列出每一处引用的位置。
  • 同一页内的链接写 #id，同样有预览。
  • 图片语法 ![](/page#id) 不用于引用。理由：它和真正的图片无法区分。

字段类型默认值作用
title字符串必填页面标题和 <title>
eyebrow字符串无标题上方的一行小字
layoutessay | paper | bento | 博客自定义的版式名essay选择版式，见 扩展接口
themethemes/ 下的文件名bake.config.js 的 theme选择主题
widthnormal | widenormal正文宽度。normal 是 --measure，wide 是 --measure-wide，两个值由主题设定
toc布尔true是否显示目录
numbered布尔false标题是否自动编号，paper 版式默认 true
authors字符串列表无paper 版式的作者行
abstract字符串无paper 版式的摘要
draft布尔false为 true 时 bake build 不生成这一页，bake dev 照常显示

以上字段由 bake 校验，类型不符时构建报错。其他字段（例如 category、summary、tags）bake 不解释，原样放进站点数据，供首页这类组件使用，见 扩展接口。

Markdown 的输出格式是什么

编辑器保存时用 remark-stringify 输出 Markdown，往返测试要求载入后不修改直接导出的结果与原文件逐字节相同。为此输出格式固定如下，示例博客的文件也按这个格式书写：

项目输出
无序列表符号-
强调和加粗*斜体*、**加粗**
代码块三个反引号加语言名
标题ATX 形式（##）
块之间一个空行
文件末尾一个换行符

已有文件不符合这个格式时，第一次保存会改变这些写法。迁移博客时先用 bake format 统一一次，之后的 diff 只包含实际修改。
