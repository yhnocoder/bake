内容格式

本文档定义 bake 接受的 Markdown 写法：基础语法、内置块类型、公式、旁注、站内引用和 frontmatter。渲染模块和编辑器都从内容格式模块取定义，这里写下的每一种写法，在编辑器里都能编辑，在页面上都能显示。

写法只有一套来源：src/format/ 的 remark 插件组合和块类型登记表。新增一种写法时，先在这里登记，渲染和编辑器同时获得它。

基础语法是什么

正文是 CommonMark 加 GFM（表格、删除线、任务列表、脚注），再加公式（remark-math）、指令块（remark-directive）和文字标记 ==文字==。不认识的指令名在构建和编辑器载入时报错，报错信息包含文件路径和行号。

remark 插件提供的写法
remark-gfm表格、删除线、任务列表、脚注（用作旁注）
remark-math行内公式 $...$、独立公式 $$...$$
remark-directive:name[]{}、::name[]{}、:::name 三种指令
remark-cjk-friendly、remark-cjk-friendly-gfm-strikethrough中文标点旁边的 **、*、~~ 正确识别，例如 中文**加粗：**后面
属性扩展 src/format/attributes.js标题和图片后面的 {#id key=value}，写法与 Pandoc 的属性语法相同，不支持 Pandoc 的 .class。bake 自己实现
高亮扩展 src/format/highlight.js==文字==，标记是恰好两个 =，两侧的判定规则与 remark-cjk-friendly 对 * 的规则相同，所以 中文==重点：==后面 能识别。bake 自己实现
块引用 id 扩展 src/format/block-id.js段落末尾的 ^block-id，见 站内引用怎么写。bake 自己实现

基础语法按 CommonMark 的规定输出 HTML。代码块输出 <pre><code class="language-python">，语言名写在 class 里。

属性、高亮和块引用 id 三个扩展各自包含解析和输出两部分。理由：现有的 remark 插件要么没有输出规则，写回时报错或丢失属性，要么把正文里的 = 转义成 \=，往返测试无法通过。

段落里能不能写 HTML

不能。段落、标题、列表和表格单元格里出现 HTML 标签时构建报错。只用一次的特殊内容写成独立的 HTML 块：前后各空一行，块内是完整的 HTML。编辑器里显示它的渲染结果，点开后编辑源码。

同一种写法用到第二次时，把它做成块类型或文字标记：所有博客都可能用到的加进 bake 的 src/blocks/，只有一个博客使用的加在该博客的 blocks/。理由：HTML 在编辑器里只能按源码编辑，块类型才能在编辑器里直接输入。

内置块类型长什么样

下面每一节给出一种内置块类型的写法和渲染结果。渲染结果是 bake 内置样式的默认效果：颜色、字体和宽度取自主题变量，主题只改变量值，版面结构不变。指令有三种形式，对应块类型定义里的 form：:name 是行内标记（text），::name 是单行块（leaf），:::name 是可以包含段落的块（container）。容器嵌套时外层多写一个冒号。块类型的定义方式见 扩展接口。

每个指令块输出的最外层元素、每个组件元素和每条旁注的 <aside> 带 data-md 属性，值是这个节点在源文件中的原文，按语法树记录的位置从源文件截取。发布的页面在复制时直接使用它，见 编辑器 的复制与粘贴一节。

标题 id 和目录短标题

标题后的 {#id} 设定锚点，toc 设定目录里显示的短标题。{#id} 里的 id 以字母开头，只含字母、数字、- 和 _。标题只接受 id 和 toc 两个属性，其他属性和 .class 报错。鼠标移到标题上时，左侧显示 # 链接。编辑器里标题左侧显示 id，在属性面板里修改。

标题输出为 <h2 id="chain-rule"><a class="anchor" href="#chain-rule" aria-hidden="true">#</a>反向传播中的链式法则</h2>。没有写 {#id} 时，id 由 github-slugger 从标题文字生成：保留中文，字母转为小写，空格换成 -，去掉标点；生成 id 时不计入标题里的公式和旁注引用。同一页里重复时依次加 -1、-2。生成的 id 与页面里显式写的 id（标题的 {#id}、^block-id、公式编号）相同时，生成的 id 也加后缀。标题文字只有标点、生成的 id 为空时报错，需要写 {#id}。目录包含 h2 和 h3。有 toc 属性时目录项显示它的文字；没有时显示标题内容渲染后的 HTML，公式同样显示为 SVG，不含 # 链接和旁注引用。

图片

图片用 Markdown 的图片语法，说明文字同时用作 alt 和图注。图片必须独占一段，段落里还有其他文字时报错。图片文件放在文章所在目录的 assets/。编辑器里粘贴或拖入图片时，文件自动存进 assets/。

支持的格式：SVG、PNG、JPEG（.jpg、.jpeg）、GIF、WebP、AVIF。其他扩展名构建报错。构建时怎样处理每种格式见 构建与开发服务器。

图片后面紧跟一组 {} 属性时，可以设定尺寸和排法。表外的属性报错：

属性取值默认值作用
width数字加 px、% 或 em，只写数字时按 px图片原始宽度，最宽为正文宽度显示宽度。% 相对于正文宽度
height同 width按宽度和原始比例计算显示高度。只写一个时另一个按原始比例计算；两个都写时图片按比例缩放到框内，不变形
floatnone | left | rightnonenone 时图片独占一行并居中；left 或 right 时图片靠左或靠右，后面的文字环绕在另一侧

图片输出为 <figure class="image float-left">，里面依次是 <img src="./assets/neuron.svg" alt="神经元" style="width: 160px"> 和 <figcaption>神经元</figcaption>。float 为 none 时没有 float-* 类。width 和 height 写进 style，只写数字时加 px。说明文字为空时没有 <figcaption>。

浮动图片的宽度最多是正文宽度的 50%，与环绕文字之间留 1.5em 间距。窗口宽度小于 600px 时浮动取消，图片独占一行。理由：窄屏上剩下的宽度放不下几个字，环绕的文字会变成一列一两个字。

组件

有图题时写 :::name{属性}，容器里的文字是图题；没有图题时写 ::name{属性}。指令名包含 - 时按组件处理，组件不能写成行内形式 :name。组件名不存在、属性不在组件的 static properties 中或类型不符时报错。输出同名 custom element，带 class="component"，例如 <gradient-figure x0="1.5" class="component" data-md="…"><figcaption>图题</figcaption></gradient-figure>。属性值等于 static properties 中 default 的属性不写进元素；没有图题时元素内没有 <figcaption>。组件自己决定画什么，bake 只提供组件与前后内容的间距和图题的样式，不加边框。编辑器里组件照常运行，属性面板修改参数，图题直接输入。

旁注

旁注是带编号的注释：正文里显示上标数字，注释放在右侧栏，与编号所在的行对齐。写法是 GFM 脚注，注释里可以写任意 Markdown，包括公式、链接、列表和多个段落。和边注的区别是旁注指向正文里的一处位置，悬停时高亮被注释的内容。

反向传播从损失函数开始，沿计算图逆向逐层计算梯度。

每一层的梯度都由上一层传回的梯度乘以本层的局部导数得到[^d]。局部导数只依赖本层的输入和输出，所以每一层可以独立计算，再按顺序连乘起来。

[^d]: 局部导数是本层输出对本层输入的导数 $\partial y / \partial x$。

    注释可以有多段，后面的段落缩进四个空格。

最后得到的是损失对每个参数的梯度。优化器用这些梯度更新参数，进入下一轮前向传播。

反向传播从损失函数开始，沿计算图逆向逐层计算梯度。

每一层的梯度都由上一层传回的梯度乘以本层的局部导数得到1。局部导数只依赖本层的输入和输出，所以每一层可以独立计算，再按顺序连乘起来。

1 局部导数是本层输出对本层输入的导数 ∂y/∂x。

图中是鼠标停在注释上时的样子：被注释的段落显示 --color-highlight 背景，上下两段不变。

  • 编号按引用在正文中出现的顺序从 1 开始生成。[^d] 里的名字只用于对应，不显示。
  • 鼠标移到注释上时，正文里被注释的内容高亮；鼠标移到正文的编号上时，对应注释高亮。默认高亮编号所在的整个段落。
  • 需要精确范围时写 :span[被注释的文字][^d]，只高亮方括号里的文字。:span 后面必须紧跟一个脚注引用。
  • 定义了但没有被引用的注释，以及引用了但没有定义的注释，构建报错。
  • 同一条注释只能引用一次，引用第二次时报错。理由：每条注释在右侧栏只显示一次，只能和一处位置对齐。
  • 注释里不能再写脚注引用，写了时报错。理由：注释本身已经在右侧栏，嵌套的注释没有位置可以放。
  • 注释可以为空，写作 [^d]:，页面上显示一条只有编号的空注释。编辑器插入编号后还没有输入内容时就按这个写法保存。
  • 编辑器保存时，注释定义写在第一次引用它的块之后，规则见 输出格式。理由：读源码时注释和正文挨在一起，往返测试也依赖这个固定位置。

生成的页面里，正文中的引用输出为 <sup class="sidenote-ref" id="sn-ref-1"><a href="#sn-1">1</a></sup>，注释输出为 <aside class="sidenote" id="sn-1" data-md="…"><span class="sidenote-number">1</span><div class="sidenote-body">注释内容</div></aside>。注释内容放在 div.sidenote-body 中，页面和编辑器使用同一个结构和同一套 CSS。注释的位置：

  • 引用在段落里时，注释放在这个段落之后。段落在提示框、列表项等块里时，注释也在同一个块里。
  • 引用在标题里时，注释放在标题之后。
  • 引用在表格里时，注释放在整个表格之后。

:span[文字][^d] 输出 <span class="sidenote-span" data-sidenote="1">文字</span>，后面接上述引用。悬停时的高亮范围由页面上的脚本根据这两个属性确定。

旁注和边注的排版：CSS 把 .sidenote 放进右侧栏，没有脚本时注释也在段落旁边显示。对齐脚本只做两件事：

  1. 一次读取全部编号的纵向位置，再一次写入全部注释的位置。一条注释的顶部低于上一条注释的底部加 12px 间距时，按编号位置放置；否则往下推到上一条注释底部加 12px。边注按它前面段落的顶部位置放置。
  2. 字体加载完成（document.fonts.ready）、正文容器尺寸变化（ResizeObserver）、折叠块展开或收起时，重新执行第 1 步。

读和写分成两批。理由：交替读写会让浏览器对每条注释都重新计算一次布局。

高亮使用 CSS Custom Highlight API：把被注释的文字范围登记为一个 Highlight，由 ::highlight(sidenote) 设定背景色。这个方式不修改 DOM，高亮不会引起重新排版。浏览器不支持这个 API 时不显示高亮，其他功能不受影响。

卡片网格

公式怎么写

行内公式写 $...$，独立公式写 $$...$$，独立公式可以用 \label{eq:name} 编号，正文用 \eqref{eq:name} 引用。全站共用的宏写在 bake.config.js 的 math.macros，构建和编辑器读取同一份配置。

构建时公式渲染成 SVG，页面不加载 MathJax。每个公式的元素带 data-tex 属性保存 TeX 源码，用于复制，见 编辑器 的复制与粘贴一节。组件内部需要在浏览器里渲染公式时，组件类声明 static runtimeMath = true，bake 只在用到这个组件的页面加载 MathJax。

渲染使用 MathJax 4（@mathjax/src）和 New Computer Modern 字体（@mathjax/mathjax-newcm-font）。TeX 输入加载 base、ams、newcommand、configmacros 四个包，宏取自 math.macros。公式的 HTML：

写法输出
行内公式 $...$<span class="math" data-tex="TeX 源码"><svg>…</svg></span>
独立公式 $$...$$<div class="math display" data-tex="TeX 源码"><svg>…</svg></div>，带 \label{eq:name} 时加 id="eq-name"（: 换成 -）
$\eqref{eq:name}$<a class="eqref" href="#eq-name">(1)</a>

编号由 bake 处理，MathJax 不保存公式之间的状态。含 \label{eq:name} 的独立公式按在页面中出现的顺序从 1 开始编号，渲染前把 \label{eq:name} 换成 \tag{n}。一个公式里有多个 \label（例如 align 环境）时每个都编号，外层元素的 id 取第一个 label，指向其中任一个 label 的 \eqref 都链接到这个 id。同一页里两个 \label 同名时报错。\eqref{eq:name} 不交给 MathJax，直接输出上表中的链接，它必须是所在公式的全部内容。理由：每个公式的渲染结果只取决于它自己的源码，可以按源码缓存。

渲染结果按「行内或独立」加 TeX 源码缓存，同一个公式只调用 MathJax 一次。SVG 输出使用 fontCache: 'global'：每个公式的 SVG 用 <use href="#MJX-…"> 引用字形，一页用到的全部字形放在字形容器 <svg id="math-defs" style="display:none"><defs>…</defs></svg> 里，放在 <body> 开头。理由：同一个字形在一页里只出现一次，页面体积小。

页面上只有这一个字形容器。开发服务器更新正文、编辑器渲染新公式、预览卡片显示其他页面的公式时，都只向容器加入缺少的字形，不删除已有的字形。理由：不再使用的字形不影响显示，删除字形需要追踪每个字形的使用者。

TeX 语法错误、未定义的宏和 \eqref 指向不存在的 \label 时构建报错，位置是公式在源文件中的行列。

站内引用怎么写

站内链接就是普通 Markdown 链接，不加新语法。链接到站内页面时，鼠标停留在链接上会弹出预览卡片，显示目标内容。

这里用到的是[链式法则](/matrix-calculus/deep-learning#chain-rule)。

链式法则把复合函数的导数写成各层导数的乘积。 ^chain-rule-def
链接目标写法预览显示
一篇文章/topic/page标题和导语
一个标题/topic/page#heading-id这个标题下的整节，到下一个同级或更高级标题为止
一个段落/topic/page#block-id，段落末尾写 ^block-id这个段落
  • ^block-id 是 Obsidian 的块引用写法，写在段落最后，前面有一个空格，页面上不显示。它在页面上成为段落的 id。
  • 站内链接指向的文章、标题或段落不存在时，构建报错，报错列出每一处引用的位置。
  • 同一页内的链接写 #id，同样有预览。
  • 页面内的 id 包括标题 id、^block-id 和公式编号的 id，同一页里重复时报错。
  • 图片语法 ![](/page#id) 不用于引用。理由：它和真正的图片无法区分。

frontmatter 有哪些字段

frontmatter 的字段分三类：所有文章都适用的通用字段，由版式声明的版式字段，以及 bake 不解释、原样交给组件的其他字段。

---
title: 大模型里的激活函数
slug: llm-architecture/activation
date: 2026-09-20
layout: essay
theme: blue
width: normal
eyebrow: LLM Architecture Notes · 2026-09
toc: true
category: arch
summary: 从 ReLU 到 SwiGLU，比较各函数的输出、导数和极限行为
tags: [GELU, SiLU, GLU]
---

这个例子里，title 到 width 是通用字段，eyebrow 和 toc 是 essay 版式的字段，category、summary、tags 是交给首页组件的字段。

通用字段

字段类型默认值作用
title字符串必填页面标题和 <title>
slug一段或多段，段之间用 / 分隔，每段只含小写字母、数字和 -；首页写 /必填页面地址 /<slug>/，规则见 构建与开发服务器
dateYYYY-MM-DD无写作日期。Bake v0.1 只校验格式，不参与地址
layoutessay | paper | bento | 博客自定义的版式名essay选择版式
themethemes/ 下的文件名bake.config.js 的 theme选择主题
widthnormal | widenormal正文宽度。normal 是 --measure，wide 是 --measure-wide，两个值由主题设定
draft布尔false为 true 时 bake build 不生成这一页，bake dev 照常显示

版式字段

每个版式声明自己需要的字段，声明方式见 扩展接口 的版式一节。文章选了哪个版式，就可以使用这个版式的字段。内置版式的字段如下：

版式字段类型默认值作用
essayeyebrow字符串无标题上方的一行小字
toc布尔true是否显示左侧目录
numbered布尔false标题是否自动编号
paperauthors字符串列表无标题下方的作者行
abstract字符串无作者行下方的摘要
toc布尔false是否在摘要后显示目录
numbered布尔true标题是否自动编号
bento没有版式字段

校验规则

  • 通用字段和当前版式声明的字段由 bake 校验，类型不符或取值不在范围内时构建报错。
  • 文章使用了另一个版式的字段时构建报错。例如 essay 文章写了 authors。理由：这种情况通常是切换版式后忘了删字段，字段在页面上不会显示。
  • 其他字段 bake 不解释，原样放进站点数据，供首页这类组件使用，见 扩展接口。
  • 编辑器的页面属性面板列出通用字段和当前版式的字段，控件按字段类型生成。

Markdown 的输出格式是什么

编辑器保存时用 remark-stringify 输出 Markdown，往返测试要求载入后不修改直接导出的结果与原文件逐字节相同。为此输出格式固定如下，示例博客的文件也按这个格式书写：

项目输出
无序列表符号-
强调和加粗*斜体*、**加粗**
代码块三个反引号加语言名
标题ATX 形式（##）
块之间一个空行
文件末尾一个换行符
指令和属性的值值里没有空白、引号、<、=、>、反引号、} 时不加引号，例如 {kind=note}、{x0=1.2}、{span=2x1 title=ReLU}、{toc=链式法则}；否则加双引号。标题和图片的属性 #id 在前，其余按属性表的顺序
表格单元格两侧各一个空格，分隔行写成 | - | -: |，列不按宽度对齐
有序列表起始编号保留原值，后续编号依次递增，例如 1. 1. 1. 输出为 1. 2. 3.
硬换行行尾反斜杠
旁注定义的位置写在第一次引用它的块之后。这个块是正文的顶层块，例如引用在提示框里的段落中时，定义写在整个提示框之后。同一个块引用了多条注释时，按引用顺序排列
frontmatter原文不变

已有文件不符合这个格式时，第一次保存会改变这些写法。迁移博客时先用 bake format 统一一次，之后的 diff 只包含实际修改。

模块接口

src/format/index.js 导出四个函数，渲染模块和编辑器通过它们读写 Markdown：

parse(source, { path, blocks, components, layouts, themes })
  // → { tree, frontmatter, messages }
stringify(tree)   // → string
format(source)    // → string，等于 stringify(parse(source).tree)
parseSyntax(source, { path })
  // → { tree, messages }

parseSyntax 只报告解析阶段的错误，即属性语法和 frontmatter 的 YAML 语法，不检查指令名、组件和版式。bake format 不读取博客的扩展目录，所以使用它。

参数或返回值内容
blocks博客 blocks/ 里的块类型定义列表，与内置块类型合并，重名时报错
components{ 组件名: static properties }
layouts{ 版式名: fields }
themes主题名列表
treemdast 语法树。高亮是 mark 节点；标题和图片的属性在节点的 data.attributes；段落的块引用 id 在 data.blockId
frontmatter填入通用字段和当前版式字段默认值后的对象，其他字段原样保留
messages每项是 { path, line, column, text }，text 是英文的错误说明，打印为 文件路径:行:列 错误说明，与 构建与开发服务器 的错误格式相同

components、layouts、themes 没有传入时，跳过对应的检查。

src/render/index.js 导出 render，把一篇文章渲染成正文 HTML 片段和目录。版式、构建和开发服务器从它取数据：

await render(source, { path, config, blocks, components, layouts, themes })
  // → { page, html, toc, mathDefs, ids, links, components, messages }

render 是异步函数，因为 MathJax 按字符范围加载字体数据。config 是 bake.config.js 的内容，用到其中的 math.macros；其他参数与 parse 相同。

返回值内容
pageparse 返回的 frontmatter，版式字段已填入默认值
html正文 HTML 片段，旁注已放在对应段落之后
toc[{ id, html, depth }]，包含 h2 和 h3。html 是目录项的内容：有 toc 属性时是它的文字（已转义），没有时是标题内容渲染后的 HTML，不含 # 链接和旁注引用
mathDefs这一页的公式用到的全部字形，形式为 <svg id="math-defs" style="display:none"><defs>…</defs></svg>，放在 <body> 开头；没有公式时为空字符串
ids页面内的全部 id：标题、^block-id、公式编号
links站内链接 [{ href, line, column }]。以 / 或 # 开头的链接是站内链接，href 的路径部分统一为带末尾 / 的形式，? 和 # 之后的部分不变，HTML 里的地址同样改写。路径最后一段带扩展名的链接（例如 /assets/a.pdf、/feed.xml）指向文件，不改写，也不进入 links。config.base 由构建加上，这里不加
components正文用到的组件名
messagesparse 的错误加上渲染的错误，格式与 parse 相同，例如 content/a.md:12:5 \eqref target eq:grad is not defined

跨页面的站内链接检查由构建完成，render 只返回检查需要的 ids 和 links。
