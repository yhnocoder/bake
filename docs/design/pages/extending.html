扩展接口

博客通过四种方式扩展 bake：组件、块类型、版式和主题。四种方式都是把文件放进约定的目录，bake 按目录发现它们，配置文件不需要登记。

bake 怎么发现扩展

扩展位置名字
全局组件components/*.js文件名
主题组件content/<主题>/components/*.js，<主题> 是 content/ 下第一层目录文件名
块类型blocks/*.js文件名，必须与默认导出的 name 相同
版式layouts/*.js文件名
主题themes/*.css文件名

每个扩展目录只发现第一层的文件。子目录不发现，用于存放共用的模块，例如 components/lib/、blocks/lib/、themes/lib/。

一个页面所属的主题是它的路径在 content/ 下的第一层目录名，例如 content/matrix-calculus/deep-learning.md 属于主题 matrix-calculus。直接放在 content/ 下的页面不属于任何主题，只能使用全局组件。

bake 在 Node 中通过 Vite 载入博客的 bake.config.js、组件、块类型和版式。扩展在发现时校验，未通过校验的扩展不使用，错误的处理见 扩展出错时会怎样。

组件怎么写

组件是用代码画的交互图。components/（全局）和 content/<主题>/components/（只在这个主题的文章里可用）下的每个 .js 文件定义一个 custom element，元素名就是文件名。文件名必须包含 -，这是 custom element 的命名规则。

export default class GradientFigure extends HTMLElement {
  static properties = {
    x0: { label: 'x₀ 初始值', type: 'number', min: -2, max: 2, step: 0.01, default: 1.2 },
    showPath: { label: '显示路径', type: 'boolean', default: true },
  };
}

bake 对组件的要求：

要求理由
文件名以小写字母开头，只含小写字母、数字和 -，至少包含一个 -，不是 HTML 规范保留的名字（例如 font-face）custom element 的命名规则
默认导出一个继承 HTMLElement 的类，bake 用文件名调用 customElements.define组件不需要自己注册，改名只改文件名
static properties 列出可调属性，可以省略。字段为 label、type（number | string | boolean | enum）、default，以及 min、max、step、options。enum 必须有非空的 options；min、max、step 只用于 number；default 必须符合类型和取值范围编辑器据此生成属性面板；bake 据此生成 observedAttributes
属性变化时重画（attributeChangedCallback）属性面板修改属性时组件实时更新
保留元素内原有的 <figcaption>图题是 Markdown 内容，由编辑器管理
模块顶层不访问 DOM，只在类的方法里访问bake 在 Node 中载入组件模块读取 static properties，Node 中只有一个空的 HTMLElement 类

bake 在 Node 中通过 Vite 载入组件模块，读取 static properties，不执行 customElements.define。在 Node 中，bake/runtime 解析到替代实现：site 为 { pages: [], config: {} }，其他函数调用时报错。组件可以导入 components/lib/ 中的文件、CSS 文件等 Vite 能处理的模块。开发服务器修改组件或它导入的文件后，bake 重新读取 static properties，不需要重启。bake.config.js 用同样的方式载入。

开发服务器中，组件文件修改后页面不刷新，组件实例换成新的实现。bake 为每个组件注册一个包装类：包装类构造元素时使用当前的实现类，把生命周期回调和属性变化转发给元素自己的实现，observedAttributes 来自 static properties。组件模块热更新时，包装类换用新的实现类，并把页面上这个名字的每个元素替换成新元素：新元素使用当前的属性和元素第一次连接时原有子节点的副本，所以属性不变，图题保留，旧实现生成的内容不会带到新元素中。理由：一个 custom element 名字只能注册一次，直接重新注册会失败。注册时的 observedAttributes 不随热更新改变，新增的属性在刷新页面后才响应变化。

组件用纯 JavaScript 编写。组件可以从 bake/runtime 导入以下工具，只导入用到的工具时，页面只加载对应的代码：

导入作用
animateMotion（motion）的 animate，参数和返回值与它相同。每次调用时检查系统是否开启减少动态效果，开启时改用 createScopedAnimate({ skipAnimations: true }) 创建的函数，属性直接设为最后一帧，finished 立即完成。理由：Motion 自带的 reduceMotion 选项只关闭位移类动画，透明度等动画仍然进行
layoutTextlayoutText({ text, font, width, lineHeight }) 返回 { lines: [{ text, width }], height }，height 是行数乘 lineHeight。font 是 canvas 的字体写法，例如 16px "LXGW WenKai Screen"；width 和 lineHeight 是像素数。使用 Pretext（@chenglou/pretext）断行，用于 SVG 和 canvas 里的文字。字体载入完成后 bake 清除 Pretext 的宽度缓存，组件在 document.fonts.ready 之后排版
renderMathrenderMath(tex, { display = false }) 返回 Promise<SVGSVGElement>，使用站点的 MathJax 配置和宏。SVG 自带它用到的字形，不引用页面上的字形容器。理由：组件可能使用 shadow DOM，shadow root 里找不到页面上的字形。MathJax 在第一次调用时才加载，没有调用的页面不加载。同一公式每次调用返回新的元素。TeX 有错误时 Promise 以 Error 拒绝，说明是 MathJax 的错误文字
site站点数据，见 组件怎么取得站点数据

组件名在全站唯一，主题组件与全局组件重名、两个主题的组件重名时构建报错。一个主题的组件被另一个主题的文章或 content/ 下第一层的页面使用时构建报错，提示把它移到全局 components/。components/lib/ 下的文件是组件共用的模块，不定义组件。

块类型怎么定义

块类型是扩展的 Markdown 写法。bake 的内置块类型在 src/blocks/，博客自己的块类型在 blocks/，每个文件定义一种，格式相同。

export default {
  name: 'shape',
  form: 'text',
  attributes: {
    kind: { type: 'enum', options: ['scalar', 'row', 'column', 'matrix'], default: 'scalar' },
  },
  render: ({ attributes, children }) => ['span', { class: `math-shape ${attributes.kind}` }, children],
};
字段说明
name指令名，必须与文件名相同，只含小写字母和数字并以字母开头。不能包含 -，因为指令名包含 - 时按组件处理。博客的块类型与内置块类型重名时构建报错。理由：与组件、版式、主题一样按文件名命名，找定义时直接看文件名
formtext：行内标记，写作 :name[文字]{属性}；leaf：单行块，写作 ::name[文字]{属性}；container：可以包含段落的块，写作 :::name{属性} 到 :::
label插入菜单里显示的名字，默认是 name
attributes属性定义，字段与组件的 static properties 相同，编辑器据此生成属性面板
render可选。参数 attributes 是写在指令上的属性，未写的属性填入默认值，值都是字符串；label 是容器形式 [标题] 转换成的 hast 节点列表，没有方括号时为 undefined；children 是其余内容转换成的 hast 节点列表。children 要按原顺序连续放在同一个父元素里，label 放进一个单独的元素，这个元素也放在同一个父元素里，编辑器用这两处作为可输入的区域。返回 hast 风格的数组 [标签, 属性, 子节点列表]，子节点列表里可以是 hast 节点、字符串或同样形式的数组。bake 在返回的最外层元素上加 data-md。不写时输出 <div class="name">（text 形式为 <span>），属性写成 data-*

块类型文件在 Node 中用于渲染，在浏览器中用于生成编辑器节点，所以只能导入在两种环境都能运行的模块。编辑器打开之后再修改块类型定义，阅读视图立即更新，编辑器在刷新页面后使用新定义。理由：浏览器不会重新执行已载入的模块，修改块类型定义是开发扩展时的操作。

块类型的样式写在博客的主题 CSS 里。编辑器中块内的内容可以直接输入，渲染结果与页面相同。理由：render 的输出同时用作编辑器节点的 DOM，编辑器和页面不需要两套定义。

版式怎么写

版式决定正文周围的页面结构。内置三种：

版式结构
essay左侧目录、中间正文、右侧旁注栏
paper标题、作者行、摘要，正文单栏，标题自动编号，旁注栏在右侧
bento标题和导语，下方是整页宽度的卡片网格，没有目录和旁注栏

博客可以在 layouts/ 中新增版式，或用同名文件覆盖内置版式，覆盖时函数和 fields 一起替换。版式文件默认导出一个函数，返回 <body> 内的 HTML：

export default function essay({ page, html, toc, site }) {
  return `
    <header class="mast">
      ${page.eyebrow ? `<p class="eyebrow">${page.eyebrow}</p>` : ''}
      <h1>${page.title}</h1>
    </header>
    <nav class="toc">${toc.map(t => `<a href="#${t.id}">${t.html}</a>`).join('')}</nav>
    <article>${html}</article>`;
}
参数内容
pagefrontmatter 全部字段，版式字段已经填入默认值，加上 url 和 path（源文件相对路径）
html渲染好的正文 HTML，旁注已经放在对应段落之后
toc目录项列表 { id, html, depth }，html 是目录项的 HTML，有 toc 属性时是它的文字，没有时是标题内容渲染后的 HTML
site站点数据，与组件取得的相同

版式需要的 frontmatter 字段由版式文件导出 fields 声明：

export const fields = {
  authors: { label: '作者', type: 'list' },
  abstract: { label: '摘要', type: 'string' },
  toc: { label: '目录', type: 'boolean', default: false },
  numbered: { label: '标题编号', type: 'boolean', default: true },
};

字段定义的格式与组件的 static properties 相同，另外支持 list（字符串列表）类型。bake 用它校验文章的 frontmatter，把默认值填进 page，并在编辑器的页面属性面板里生成控件。版式字段不能与通用字段同名，同名时构建报错。

<head>、主题 CSS、组件脚本、旁注对齐脚本、预览脚本和复制脚本由 bake 加入，版式不处理。编辑器挂载在版式输出的 <article> 上，所以每个版式必须输出且只输出一个 <article>，正文放在其中。

bake 每页只调用一次版式函数，html 参数先传入占位注释 <!--bake:article-->，检查输出中 <article> 开始标签恰好一个、占位注释恰好一个并位于这个 <article> 之内，通过后再把占位注释换成正文。不通过时报错 Layout <名字> must output exactly one <article> that contains the page content，这一页不输出。理由：正文中独立的 HTML 块可能包含 <article>，所以检查在放入正文之前进行。

版式和 bake 的 CSS 通过以下 class 对应：

class由谁加作用
<main class="layout-essay">内置版式，layout-paper、layout-bento 同理选择这个版式的栅格
<article class="numbered">版式，frontmatter 的 numbered 为 true 时h2 和 h3 用 CSS 计数器编号，essay 和 paper 共用同一段规则
<body class="wide">bake 生成整页时，frontmatter 的 width 为 wide 时正文宽度改用 --measure-wide

主题怎么写

themes/ 下每个 CSS 文件是一个主题，文件名是主题名。主题设定 bake 规定的 CSS 变量，也可以写博客自己的块类型和组件的样式。bake 的版式和内置块只使用这些变量，不写具体颜色。

:root {
  --font-body: 'LXGW WenKai Screen', serif;
  --font-mono: 'JetBrains Mono', monospace;
  --font-serif: 'Source Serif 4', 'Noto Serif SC', serif;
  --color-text: #1f2328;
  --color-muted: #656d76;
  --color-bg: #fbfaf7;
  --color-accent: #2f6fb3;
  --color-mark: #f5e6c8;
  --color-mark-text: #a0574a;
  --color-highlight: #e6f0ff;
  --color-border: #e3e0d8;
  --measure: 42rem;
  --measure-wide: 60rem;
  --sidenote-width: 16rem;
}

--color-highlight 是旁注悬停时正文的高亮色，--color-mark-text 和 --color-mark 是 ==文字== 的文字颜色和底色。主题缺少某个变量时，构建报错并列出缺少的变量。变量名列表是 src/styles/variables.js 的 themeVariables，检查主题时使用它。检查只读主题文件本身，收集文件中任意选择器下声明的自定义属性。

几个主题可以把共用的样式放在 themes/lib/，用 @import './lib/blocks.css' 导入，themes/lib/ 下的文件不是主题。被导入的文件里声明的变量不计入检查，每个主题文件自己写出全部变量。

代码高亮的颜色使用 13 个可选的代码变量，列在同一文件的 optionalVariables，检查主题时不要求它们。主题不写某个代码变量时，它回退到下表的主题变量。理由：只设定必需变量的主题也有代码颜色，深色模式只需要换变量的值。

代码变量回退
--code-foreground--color-text
--code-token-keyword--color-accent
--code-token-comment--color-muted
--code-token-string、--code-token-string-expression--color-mark-text
--code-token-constant、--code-token-parameter、--code-token-function、--code-token-punctuation、--code-token-link、--code-token-inserted、--code-token-deleted、--code-token-changed--color-text

examples/minimal/themes/default.css 写出了全部 13 个代码变量，供主题作者参考。

组件怎么取得站点数据

首页是 content/index.md，首页的卡片网格是博客的全局组件 topic-grid。组件从 bake/runtime 导入 site 取得站点数据：

import { site } from 'bake/runtime';

site.pages;
site.config;
字段内容
site.pages全部非草稿页面的列表，每项是 { url, title, ...frontmatter }，按路径排序
site.configbake.config.js 中的 site 字段，例如首页分类

导入 site 的组件模块在站点数据到达后才执行，组件里可以直接读 site.pages。构建后 site 从 <base>site.json 读取，地址带 bake.config.js 的 base。只有导入了 site 的组件所在页面才请求这个文件，同一页面只请求一次；请求失败时导入它的组件不注册。开发服务器中，页面增删或 frontmatter 修改后 site.pages 和 site.config 换成新值，然后在 document 上派发 bake:site 事件，组件监听它重画：

connectedCallback() {
  this.redraw = () => this.draw();
  document.addEventListener('bake:site', this.redraw);
  this.draw();
}

扩展出错时会怎样

扩展的错误使用与文章相同的格式 文件路径:行:列 错误说明，位置是 1:1，说明是英文。模块载入失败（语法错误、导入失败、顶层抛出异常）时报告 Cannot load <文件路径>: <错误说明>，语法错误带 Vite 给出的行列。

$ bake build components/wave-figure.js:1:1 Component wave-figure is also defined in content/extending/components/wave-figure.js content/extending/components/wave-figure.js:1:1 Component wave-figure is also defined in components/wave-figure.js themes/warm.css:1:1 Theme warm is missing variables --color-mark, --measure 3 errors, dist/ was not written
  • bake build 在扩展有错误时只输出扩展的错误和汇总行，以 1 退出，不渲染页面，输出目录不变。理由：一个出错的扩展会在每个使用它的页面上产生错误，只输出原因更容易定位。
  • bake dev 启动时扩展有错误，与 bake build 一样输出错误和汇总行，不启动服务器。启动之后修改扩展产生的错误不停止服务器：跳过未通过校验的扩展，页面照常显示。错误输出到终端，并计入每个页面状态栏的错误列表。使用了被跳过的组件、块类型、版式或主题的页面另外报告对应的渲染错误。
  • 同名的两个组件都不使用；覆盖内置版式的文件出错时使用内置版式。
